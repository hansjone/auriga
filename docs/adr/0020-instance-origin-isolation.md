# 0020 实例使用独立的源

- 状态：已采纳
- 日期：2026-10-19

## 背景

契约第一版把实例放在门户同源的 `/i/<实例 id>/` 下。实例里会运行不完全可信的代码：个人上传的插件、模型生成的网页、被提示注入的页面。同源时这些代码可以借用户的门户会话调用平台接口，CSRF 令牌也能被读到。契约评审把它列为最严重的问题。

## 决定

- 有域名的部署：每个实例一个子域 `<实例 id>.<实例域>`（例如实例域 `i.example.com`），需要通配符 DNS 和通配符证书。
- 门户经 edge 的 `/open/<实例 id>` 签发一次性票据（60 秒、只能用一次、绑定会话和实例），跳到实例子域换成只对该实例有效的 `__Host-auriga_inst` cookie；edge 每次请求都检查对应的门户会话仍然有效。
- 平台的 CORS 永不放行实例来源；写请求的 CSRF 检查照旧（实例页面读不到门户源的 CSRF cookie）。
- 只有 IP、没有域名的部署退回同源路径 `/i/<实例 id>/`，属于已知的弱隔离：只面向互相信任的团队，安装向导和文档里写明。

细节见 `contracts/README.md` 的路由一节和 `contracts/plugin/README.md`。

## 后果

- 有域名的部署要多配通配符 DNS 和证书（CertMagic 用 DNS-01，或交给外部反向代理）。
- edge 要实现按 Host 路由、票据和实例 cookie。
- 实例页面里的代码拿不到平台凭据，管理接口另有 `ctx=admin` 的检查兜底。
