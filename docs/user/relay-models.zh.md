# 在 DSH 中使用团队中转站模型

管理员先在“中转站 → 模型与供应商”添加供应商和模型池、录入供应商凭据，并为成员授予模型调用权限。公开调用入口为 `https://portal.example.com/ai/v1`；模型名使用平台公布的池 ID。成员不需要供应商密钥。

桌面 DSH 使用 Auriga 插件的成员身份通道：先正常登录插件，再选择已由部署接线的成员模型提供方。调用时使用设备模型授权，平台每次核验当前成员与权限，自动建立成员用量归属。不要把管理员签发的对外 Key 当成员模型授权；仅登录成功也不代表原生模型提供方已就绪。看不到成员模型时请管理员检查插件接线和模型容量配置，不能以手工外部 Key 代替验收。

云端 DSH 使用实例交付的 `Auriga`（`auriga-managed`）提供方。在门户进入本人实例，在原生模型选择器选池模型并新建对话。托管模型授权由平台维护；不复制其中的 Authorization，也不修改用户已有个人凭据。

管理员点击“配置 Auto 默认路由”，在原有池表单为固定 ID `auto` 配置真实路由、容量与价格并确认保存。
平台已发布且本人获权的 `auto` 才会成为未显式选择用户的新对话默认；旧池、已有会话和个人模型选择保留。
运行中的云端实例约每30秒主动重新获取目录，无需重启。打开原生“模型”设置，展开 Auriga 的模型选项可查看 ID、显示名和容量、获取可用模型并按原生方式选择、取消或应用。
卡片的“重新获取平台模型”会立即检查；失联保留上次目录并显示状态，授权失效仍由服务端拒绝调用。恢复联网后可重新获取。
验收时在管理台新增一个本人获权的公开模型，保持 DSH 页面与对话运行，等待目录更新后选择该模型新建对话；随后只修改 auto 路由，确认下一次调用使用新路由且旧会话选择未变化。

管理员在“中转站 → 用量”选择成员 ID，检查新请求和非零输入/输出 token。成员 Key 的预算、RPM、并发和在途 token 上限可在管理台调整；被禁用的成员 Key 不会因下一次调用自动复活。

对外应用另由管理员在“中转站 → 虚拟 Key”签发受限 Key，设置模型范围、月预算、RPM、并发及在途 token。Key 只展示一次，安全交付应用后以 Bearer 调用公开入口。对外用量按 Key 查询，不能冒充成员用量。

401/403 请检查登录、授权、设备或 Key 状态；429 区分限速与预算不足。参数错误保留安全的 4xx 状态，上游故障为 502，超时为 504。流式中断可能按保守估算计费，管理台会显示用量质量。金额使用整数微单位，1 USD = 1,000,000 微单位。

模型提供方应保留 `supportsStore:false`；不提供响应存储功能。不把密钥填进 URL、对话、截图或工单。纯 IP/HTTP 部署仅在管理员已接受明文边界时使用 `http://192.0.2.10:8080/ai/v1`，不要关闭 TLS 校验。

已知托管同机边界见[托管模型凭据](../design/managed-model-credential.zh.md)。管理员配置和部署步骤见[中转站架构](../architecture/relay-bifrost.zh.md)。
