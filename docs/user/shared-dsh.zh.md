# Auriga DSH 共享与独立模式

共享池仅限互信团队。成员可能互相看到文件，并可能以 owner 能力操作。成员之间会话内容可见，且可能以其他成员的身份操作内部应用、审计记在被冒用者名下。同一进程卡死、崩溃或取消超时会中断全池任务。需要保密或独立故障域请使用独立容器。

## 首期已接受的风险

1. 原生 Cookie/browserPeer 可能将不同成员映射到同一 owner，/connect 也可能构造 owner。平台签名成员头不自动替换原生 Cookie、index snapshot 和 WS 身份，成员策略（包括禁 shell）可能被旁路；不能认为全部入口均为非 owner。
2. 原生 workspaceFiles/read、readBytes、stat 可接受其他成员的文件路径。绝对路径、父目录、Windows junction、硬链接可造成跨成员读取，stat 也可能泄露元数据。固定工作目录、隐藏按钮或单次 realpath 检查不能保证隔离；文件观测和下载也仍有风险。
3. 内存耗尽、同步阻塞和崩溃影响整个池。进程内无法选择性硬杀本人执行；首期只支持合作取消。等待30秒超时后，外部 supervisor 将保守停止整个池及执行树，中断其他成员任务；不保证30秒内完成停池，未确认停止时保持 blocked。任一统一资源到期或撤销同样会停止全池。
4. A 可以从原生 owner 入口打开、读取和驱动 B 的会话及历史。企业 skill 按会话归属绑定 B 的凭据时，A 的指令可能以 B 的企业身份执行业务，平台与业务审计均归 B。能力校验通过不消除此风险。首期保留这些风险；后续受控非 owner 载体、受限文件服务及外部成员执行域再增强隔离。

## 普通成员入口

登录门户首页，读取本人分配，点击“打开 Auriga DSH”。首次分配默认共享；等待、切换或不可用时刷新状态，不会退回旧会话。已获得独立容器授权并完成切换的成员仍从同一按钮进入独立容器。UAC 与邀请成员规则一致。企业 skill 只来自平台统一资源；共享模式不开放个人 Key、私有 skill、任意插件、自行共享 skill/MCP、shell 和终端，需要这些功能时向管理员申请独立容器。

## 管理切换与恢复

管理台“成员 → 详情 → Auriga DSH · 成员模式”查看模式和独立授权。管理员需具备 workspace.placements.read/write 及600秒内身份续验。填写原因，确认风险与影响再切换。提权和降权均封存本人文件30天、新模式空目录、会话始终丢弃；不自动恢复任务、.dsh、.env、模型 Key 或插件运行态。取回文件须本人显式申请，由管理员按审计流程导出、扫描并限本人工作区。

202 只表示登记。保存操作 ID，使用“读取进度 / 重试查询”观察撤销、等待停止、准备、提交或失败分类。查询失败只重试查询；提交结果不确定时先按操作 ID 查证，不盲目重发。blocked 不代表成功，不返回仍活着的旧会话；由管理员恢复编排。成功后从门户重新进入并确认空目录与新会话。

维护窗口先通知成员、提供导出窗口，再登记“继续独立”名单，逐成员重建，不迁移历史会话，不在首次登录静默销毁数据。当前冻结契约缺少管理读取成员分配与 ETag、独立授权变更、批量名单及实时容量/guardian 影响查询；这些能力在真实接线前显示不可用，不能执行批量重建。页面进度查询和门户票据接口仍需服务端实现及联合验证。

初始预算为每池20登记/4活跃、每人1活跃、5GiB/10万inode；80%内存停止准入，满载加池，不静默搬迁在途会话。这些是预算，不是实测容量。
