# M2 单机集成（Compose：能给每人起 DSH）

用 Docker Compose 把 platform（iam+org+workspace combined）、edge、NATS、PostgreSQL、节点代理（Docker 驱动）串起来，端到端验证：登录 → 冷启动 → 经 edge 访问实例 → 闲置回收 → 闹钟唤醒 → 双会话吊销。

Windows 侧不假设有 Docker CLI；本机 WSL 的 Linux Docker 或 GitHub Actions（`e2e.yml`）可运行完整栈。使用前先确认连接的是本机 daemon。有 Docker 的 Linux 可按下面步骤本机跑。

## Network submit 上游

新 bootstrap 同时生成私有 `var/network/`，材料纳入安装 receipt；重复 prepare 保留原凭据，缺失/漂移拒绝，不隐式修复旧安装。升级此配方须使用新的隔离材料目录和测试栈，保留原有数据，不手改 receipt。该目录为 `0700`、文件为 `0600`，含专用服务端 CA、submit 客户端 CA、叶证书、Broker NKeys/三组密码、协议签名私钥及固定 ai-gateway 服务票据导出配置。CA 私钥不落盘；submit 信任不与 IAM 共用。

edge 镜像附带已锁定依赖构建的 ai-gateway、network Broker 和无凭据就绪探针；Compose 用独立 `network-broker`、`network` 服务启动，分别执行正式 Broker 配置与 `--network-config`。network 与 callout/router 共享同一进程，Broker TCP `127.0.0.1:14224`、WSS `127.0.0.1:18444`，submit 在宿主 `18443` 提供强制 mTLS。该 HTTPS 端口只供持有专用客户端证书的 edge 访问，不将设备 Bearer 经明文传输。

edge 的 `upstreams.network-submit=https://host.docker.internal:18443`，`networkSubmitHop.serverName=submit.network.internal`；只挂载 `var/network-edge` 中的 edge 客户端证书/私钥和服务端 CA，读权限限定到 edge 组，不挂载 Broker 密码、服务端私钥或 ai-gateway 安装秘密。platform 从私有 `platform.properties` 启用现有固定 ai-gateway 票据导出，票据目录单独挂载并原子轮换；network 对 IAM RPC 仍使用 IAM 专用客户端证书。

network 健康检查经真实 mTLS POST 取得 `401 network.unauthorized` 后才启动 edge。`docker compose ps`、`stop`/`down` 覆盖两个新服务；不增加 `down -v` 或删除安装材料。此配方验证部署入口，不自动配置完整 collab 网络业务/协议信任发布；健康状态不等于真实设备 READY、持久化投递或双 DSH 闭环通过。

## DSH 运行时

M2 的 agent 经 `https://127.0.0.1:7443` 完成实际 CA pin TLS Join，
`ALLOW_INSECURE=true` 只允许旧开发入口，不会降级此 HTTPS 连接。
RT1 要求该响应含非空合法发行根。新空安装的 bootstrap 在进程内独立生成
`e2e-runtime-root`，只保存公开的 `var/runtime-keys/root.pb`，私钥不落盘、不输出，
不复用 IAM 身份 key。Compose 仅将该目录只读挂入 workspace 的既有 artifact-keys-directory。
根固定截止为 2031-01-01T00:00:00Z，并纳入原安装 receipt；重入只验证，
不滚动延长、不补旧 receipt 缺叶、不修复漂移。旧安装缺该材料时必须明确使用新安装目录，
不要手改 receipt。该根仅属于本次开发安装；bootstrap 在同一进程生成独立 Ed25519 私钥，为本次确切镜像签正式 RuntimeReleaseEnvelope 后立即清除私钥，不保留再次签发能力，
M2 仍不构成 RT2 安装/缓存/重启前发行校验的验收。

默认使用**极简假 DSH**（`deploy/compose/fake-dsh`）：Node HTTP + 最小 WebSocket echo，提供 `/_auriga/health` 与身份头校验，**不是** S4 真实 DSH 离线包，也**没有**真实插件 / Cordis 链路。真实模式需使用下节的 fixture、版本元数据和 `DSH_FIXTURE=real`，不能只换镜像后继续沿用假响应断言或代发心跳。

本验收**不能**解读为「真实 DSH / 真实托管插件已通过」。

## 真实 DSH 与托管插件（W3）

真实模式使用固定Linux镜像、当前renderer实际补丁、独立internal网络、非root uid、只读根和只读meta。它在完整生命周期前直接检查实际Docker加固参数、网络归属及仅实例/受信edge两个成员。验收结果以**对应固定源码与镜像**的脱敏`w3-evidence.json`为准：只有status=passed、rawHeartbeatVerified=true、lifecycleVerified=true全部成立，才能报告该轮真实HTTP交互和生命周期通过。现有E2E M2工作流默认仍验证假DSH；库测试、镜像构建或部分成功都不能替代真实运行，也不能据此声称NAS已部署。

### 构建输入与摘要交付

`real-dsh/versions.json` 记录 S4 分支提交、DSH **0.2.0-rc.2**、Node **22.19.0**、npm **10.9.3**、目标 **Linux amd64 / glibc**。完整 npm v3 锁原样取自 S4，SHA-256：

```text
7568ed6aeb263e8605332578aba9b3b099974bf2b80704afd92cc86b7afc168b
```

构建必须显式提供 `node:22.19.0-bookworm-slim@sha256:<64位摘要>`，脚本拒绝浮动 tag，并要求它与 `versions.json` 的 `nodeImage` 完全相等。该字段记录从 Docker 官方 registry 的固定 tag 解析得到的 Linux amd64 摘要、日期和命令，**独立审查仍为 pending**，来源解析不等于审批。Docker 构建实际核对 Node/npm 版本、锁摘要、每项 npm resolved/integrity，再以 `npm ci --omit=dev --include=optional --ignore-scripts --bin-links=false` 安装目标平台依赖；保留 S4 的可选原生包与执行权限处理。不支持 Alpine/musl 或 arm64。

插件源码只复制 `clients/dsh-plugin/src`、包描述与许可证。仓库已有插件 lock 的开发依赖范围与 package.json 不同步，构建只从该锁派生生产锁：去掉 dev 条目、校验直接生产版本与 package.json 精确相等，保持全部生产包的 resolved/integrity，不重新解析版本。两个锁的摘要均记入 manifest。构建上下文不复制用户 `.dsh`、公司 profile、凭据、模型配置或宿主 node_modules。

`scripts/build-real-dsh.mjs` 先将 Dockerfile 明确需要的源码/锁/元数据复制到临时白名单上下文（约 595 KB），不把根 node_modules、var 或 .git 发给 daemon；构建后清理该临时上下文。推送本地 registry 后从 RepoDigests 取得固定镜像引用，写 `var/real-dsh.json`，其中包括镜像与基础镜像摘要、版本、锁摘要和安装文件摘要清单。这个文件与对应镜像是交给 D0/主控的边界。公开构建流程会推送本机 registry 并取得精确 RepoDigest；取得制品摘要不代表完整真实 M2 或 NAS 验收完成。镜像摘要覆盖最终启动器；镜像内 `/opt/fixture/manifest.json` 是构建输入清单，不是原始 OCI manifest，也不能替代发行签名。公开 prepare 流程另从本次本地 registry 精确仓库和 digest 读取原始单平台 OCI/schema2 manifest 及其 descriptor 对应的 config，核原字节 SHA-256、descriptor 长度和 linux/amd64 平台；拒绝 index/list、重复 JSON 键、外部 URLs/data、重定向和每文件超过 4 MiB 的材料。

启动入口为 `real-dsh/start.mjs`，使用镜像内 Node 启动原版 DSH `web --patch /run/auriga/cordis.patch.yml --no-open`，即节点代理渲染的补丁（不再带 fixture 自带补丁）。`--patch` 必须放在 web app 的 `--no-open` 参数之前，否则 launcher 会把它透传并报未知参数。DSH 0.2.0-rc.2 的命令行拒绝 `--host 0.0.0.0`，所以监听地址由渲染补丁的 `webserver` 行给出（Docker 运行时 `0.0.0.0`，原生进程 `127.0.0.1`），同一补丁装载 `auriga-dsh/plugin`、写入 `trustedHosts`。原生包、插件与前端均在构建期准备；实例启动不执行 npm/pnpm。

DSH 的模块解析只接受安装/profile manifest 的依赖闭包，单独的安装目录 symlink 不足以装载插件。因此该固定 fixture 启动时物化专属 web profile manifest，只声明镜像中预装的 `auriga-dsh`，并链接到该预装目录；不会下载或安装依赖。它不能代替通用生产插件的安装、启停或用户 profile 合并验收。HOME、DSH_HOME、缓存、临时目录及工作空间都放在 `/home/dsh` 可写挂载中；本机 WSL 验证用 Linux 原生临时目录，Windows 盘挂载显示的 0777 会被 DSH credentials-local 拒绝。运行时使用 agent 分配的非 root uid、只读根文件系统与独立内部网络；补丁关闭原生启动 URL 输出，遥测保持禁用。

### Linux 复现（独占的新 M2 测试栈）

不要在已有数据的环境直接切换 fake/real。以下命令仅供有 Docker 的本地 Linux 测试环境，工人未执行；需预装仓库要求的 Java/Go/Node 工具链。先由主控解决下节接线缺口，再运行：

```bash
cd <auriga-worktree>
export COMPOSE_PROJECT_NAME=auriga-m2-new-run
export AURIGA_M2_DATA_ROOT=/var/lib/auriga-m2-new-run
export NODE_IMAGE="$(node -p 'require("./deploy/compose/real-dsh/versions.json").nodeImage')"
# versions.json 记录官方 registry 的 linux/amd64 摘要与来源；独立审查仍待完成。
export DSH_FIXTURE=real
export AURIGA_M2_HEARTBEAT_OBSERVER=1
bash deploy/compose/scripts/prepare.sh
set -a; source deploy/compose/var/compose.env; set +a
export RAW_HEARTBEAT_FILE="$PWD/deploy/compose/var/raw-heartbeats.jsonl"
node deploy/compose/scripts/heartbeat-observer.mjs &
OBSERVER_PID=$!
trap 'kill "$OBSERVER_PID" 2>/dev/null || true' EXIT
docker compose -f deploy/compose/docker-compose.yml --env-file deploy/compose/var/compose.env up -d --build --wait
sh deploy/compose/var/iam-healthcheck.sh
# platform 首次生成的应急 enrollment 需当前测试用户可读；不要打印内容。
AGENT_VOLUME="$AURIGA_M2_DATA_ROOT" \
  ENROLLMENT_FILE=deploy/compose/var/enrollment/emergency-enrollment.json \
  JOIN_TOKEN_FILE=deploy/compose/var/join/token \
  node e2e/m2.mjs
docker compose -f deploy/compose/docker-compose.yml --env-file deploy/compose/var/compose.env down -v
```

`prepare.sh` 在 real 模式自动构建、推送并选用真实模板，模板版本/名称/标签同步变化；默认 fake 行为保留。

fake/real 构建都显式设置 `--platform=linux/amd64 --provenance=false --sbom=false`，避免 BuildKit 默认 attestation 将单平台输出包装成 index；发布后仍以 registry 实际返回的单平台 manifest digest 为准，collector 继续拒绝 index/list，不替换成未经本次引用绑定的 child 摘要。fake/real 都经 `scripts/collect-runtime-proofs.mjs <image> <隔离临时根>` 收集公开原字节；CLI 只接受 `127.0.0.1:5000/auriga/{fake,real}-dsh@sha256:<64位小写hex>`，不接受任意 registry、仓库或 URL。prepare 将临时根通过 bootstrap 的 `-runtime-proofs` 参数交给首次新安装；bootstrap 校验后创建 `var/runtime-proofs/<manifesthex>/manifest.json` 与 `config.json`，receipt 覆盖两份原始文件和正式模板。producer 在 manifest/descriptor、config/rootfs/history/执行与历史 config/healthcheck 的结构边界拒绝非规范 ASCII、long-s、Kelvin simple-fold 别名；仅严格结构对象使用既定允许字段，Labels、annotations、ExposedPorts、Volumes 的用户键与合法元数据扩展保持原样。Compose 将公开 proof 目录只读挂到 `/etc/auriga/runtime-proofs`，可信本机变量 `AURIGA_AGENT_RUNTIME_PROOFS_DIR` 指向该路径；通用安装可将按受签摘要核验的相同原始 M/C 放到 agent 默认 `<AgentDir>/runtime-proofs/<manifesthex>/`，不能用 Docker save 输出或重序列化 JSON 代替。proof 目录无私钥，目录本身不赋予信任。

Docker-only 模板的 `dsh.digest`、`dsh.url`、`releaseEnvelope.archiveDigest` 全空，旧 `SignedArtifact` 不存在；正式 envelope 固定 `purpose=dsh_runtime,name=dsh,os=linux,arch=amd64,releaseSequence=1`，`artifactId/dshVersion` 对应所选 fixture，`imageDigest` 绑定实际 manifest。首次安装的独立 runtime root 私钥仅在本进程完成正式 JCS/Ed25519 签名后清除，不使用 IAM 密钥或固定测试密钥。WorkspaceTemplates 校验正式声明的形状、映射和平台筛选；它不持有 agent 的可信 keyring，不构成验签。agent 最终按固定信任根验签、核 OCI 与实际执行镜像。

重入先严格验证原 receipt、公开根、模板和原 proof，并只读核保存的 compose.keys 与本次显式 AURIGA_IAM_ENCRYPTION_KEY/AURIGA_WORKSPACE_ENCRYPTION_KEY 相容，再只读复用；忽略新的临时 proof 来源也不会修补旧材料。旧安装缺新增材料、proof/root/模板被改、fixture 或镜像摘要变化都无损拒绝，必须使用新的空安装材料目录，不允许删除 receipt、补根或覆盖同序发行。这里的序号 1 仅是隔离 M2 fixture；这些本地检查不代表真实 daemon、整栈 CI 或正式发行部署已验收。
`var/` 含应急凭据与本地测试私钥，不提交、不贴日志。仅将 `var/real-dsh.json` 和脱敏的 `var/w3-evidence.json` 交给主控；D0 独立处理 NAS 包，不运行任何 NAS 连接命令。

真实模式与 W2V 共用登录、独立 CookieJar、冷启动、实际 phase、Docker Running、edge 和双会话吊销检查，额外要求：

1. 以元数据中的精确不可变 `repo@M` 执行 `docker image inspect`，核对完整 RepoDigests 归属及真实 linux/amd64 平台。读取本次 `var/runtime-proofs/<manifesthex>/` 下原始 manifest/config，复用公开 collector 的严格校验，绑定 M 原字节、config descriptor 的 C/长度及 config 平台；生产 V 继续负责真实启动闭环。实际 Engine Id 只允许本次原 M 或 C，再固定这一个实际 Id，容器 `.Image` 与 `.Config.Image` 必须同时严格相等（兼容 Docker 27 的 C 与 Docker 29 的 M，拒绝混搭、名称/tag 和前缀）。容器内版本/锁摘要仍须与元数据一致；HTML 必须含真实 DSH boot 注入和 module 入口，假页或普通 200 HTML 不能通过。
2. 直接请求容器（绕开 edge）验证正式插件 health 字段白名单；无签名、错误签名、错主人、过期、重放和未签名健康写请求都必须为 `401 + common.unauthenticated`。正常签名必须取得真实 HTML。
3. real 模式必须指定 `RAW_HEARTBEAT_FILE`，从受控本机观察代理读取实际被 workspace 接受的心跳。先等待门锁正向请求的交互上报落稳，再持续至少65秒只访问免鉴权健康接口，要求每次健康请求都符合真实契约，至少两条实际心跳四计数均为0、health.ok=true、原始lastInteractionAt和平台lastActivityAt均不前进。心跳样本接收时间必须跨至少25秒，末条距窗口结束不超过35秒，防止开头突发请求或停止的发送器假通过。再经edge发真实用户页面请求，要求原始交互时间及平台投影同时前进；随后第二个65秒窗口再次核对实际心跳静态。全部成立后才记录rawHeartbeatVerified=true；这仍是HTTP用户交互验收，尚未覆盖完整浏览器前端操作。real模式不会代发心跳。
4. real 模式禁止脚本代发心跳；真实插件无法报活动则失败。真实闲置回收、闹钟唤醒仍必须分别同时取得 phase / Docker / edge 证据。WS 用 DSH 的 `/api/remote.mux` 原生传输，不要求假 echo；用 masked Pong 保活，并在 DELETE 紧前以唯一随机 Ping/Pong 往返证明传输仍可用。假模式在该位置重新完成文本回声。客户端持续读取控制帧，记录并回复 Close。edge 当前直接切断代理 TCP；若收到 DSH Close 帧、关闭早于或等于 DELETE 发出时间，都不能算吊销通过。

### 本机原始心跳观察

`deploy/compose/scripts/heartbeat-observer.mjs` 仅用于本机Linux测试，在宿主8082接收专用 edge DNS 身份的 mTLS 请求，经过固定回环8081及相同 CA、专用客户端证书和 `platform` DNS 校验转发至真实 combined。三类 API 在观察模式下保持同一 HTTPS origin，完整 Host 和入口 metadata 原样保留。它不合成请求、不改认证；只有真实workspace返回200才保存白名单字段：接收时间、实例UUID、四计数、交互时间、健康布尔值与版本。认证令牌只在内存原样转发，未知字段、health.problems和所有请求头都不落盘。报文最多64KiB，输出文件0600、必须是新文件，单次最多10000条。

使用上节公开步骤，在 prepare **之前**设置 `AURIGA_M2_HEARTBEAT_OBSERVER=1`。bootstrap 会生成观察器安装参数，并将三类 API 一起指向 `https://host.docker.internal:8082`，不手改 workspace upstream。观察进程必须在启动edge前运行：

```bash
cd deploy/compose
export RAW_HEARTBEAT_FILE="$PWD/var/raw-heartbeats.jsonl"
node scripts/heartbeat-observer.mjs &
OBSERVER_PID=$!
trap 'kill "$OBSERVER_PID" 2>/dev/null || true' EXIT
docker compose --env-file var/compose.env up -d
cd ../..
DSH_FIXTURE=real node e2e/m2.mjs
```

应在独立测试机运行，避免宿主8080/8081/8082/8084被其它服务占用；内部8083不发布。NAS配置不使用这个观察代理。输出与`w3-evidence.json`都是脱敏验收证据，原始var凭据文件不交付。生命周期所有严格检查结束后才将lifecycleVerified置true，任何提前失败都保留false。

失败也会写 `var/w3-evidence.json`（状态 failed、已取得的步骤、失败步骤）；缺失的证据不视为成功。HTTP 请求有 15 秒超时，异常退出清理本脚本的临时目录与 WS。脚本不自动清除实例数据或关闭外部测试栈，操作人负责按上面的 down 命令清理。

### 节点代理接线（第 2 轮已修）

- **插件平台地址**：`AURIGA_PLATFORM_URL` 不再取 gRPC 控制地址。节点代理读 `AURIGA_AGENT_INSTANCE_PLATFORM_URL`，本套 Compose 由 bootstrap 的 `access.env` 固定为 `http://auriga-instance.internal:8083`。这是每实例隔离网络上的 edge DNS alias，仅接 self/heartbeat，不能复用门户或管理 Origin。原网络、标签、edge 归属和 alias 校验继续保留；实际可达性须由整栈验证。
- **cordis.patch.yml 形状**：渲染为 DSH Loader 补丁列表：`insert` 新增 `auriga-dsh`（`auriga-dsh/plugin`，注入 webServer/connection）和每个团队 MCP 的 `@deepseek-ai/dsh-mcp-client` 行（`Authorization` 用 `!!js` 在求值时读令牌文件，令牌值不进 YAML）；`webserver` 行给监听地址/端口；`web-runtime` 行关闭 URL 输出并写 `trustedHosts`。规格补丁 `plugins.<行 id>.<键…>` 写进对应行的 config（Loader 语义：整行 config 替换，不深合并）；`webserver`、`web-runtime`、`connection`、`auriga-mcp-*` 与插件的 `trustedHosts` 由代理独占，规格补丁不能改。团队模型应写入用户设置文档中带平台标记的条目，renderer 尚未实现，遇到 `model_providers` 直接失败，不再输出 DSH 不认识的映射。
- **trustedHosts**：节点代理读 `AURIGA_AGENT_INSTANCE_PARENT_DOMAIN`（与 access 实例 parentDomain 相同，Compose 为 `i.example.com`），仍写入裸 `<实例 id>.<域>`。新的完整浏览器 Origin 包含 scheme 与8080端口，独立正式输入及消费仍属IP2接线缺口，不能以内部 alias 或未知 profile 字段绕过。DSH原生Host与插件Origin栅栏均继续保留。
- **`/api/remote.mux`**：实例WS使用完整 `http://<实例 id>.i.example.com:8080` Origin，保持身份头 `htu` 与路径绑定、跨站拒绝和原双会话吊销断言。

### 仍需主控处理

- `contracts/openapi/workspace.yaml` 的 `HeartbeatRequest.activity`、生成模型与 `WorkspaceService.heartbeat` / `Lifecycle`：协议需表达未知（建议四个计数改为可空或增加 `unknown: [字段名]`），平台对未知视为"不可回收但刷新 plugin_seen_at"，并读取 `health.ok`。在此之前插件遇未知仍暂缓心跳（并按字段名记一条告警日志）。纯 DSH 没有 IM 服务：由模板规格补丁 `plugins.auriga-dsh.imBots = "none"` 显式声明后按已知 0 上报；没有声明时仍为未知，IM 服务存在但读取失败也仍为未知。
- 真实镜像、原生依赖启动、用户操作、回收/唤醒和 WS 吊销仍需在有 Docker 的 Linux 上实际执行；不能用已有 S4 离线启动或 W2V 假 DSH 结果替代。

## 端到端脚本（`e2e/m2.mjs`）严格验证了什么

Cookie：管理台 / 门户 / 实例各用独立 jar，按 Set-Cookie 的 host、Domain、Path、Max-Age/Expires 选择。除 jar 选择单测外，脚本还将实际门户、管理台会话 cookie 手动发给实例 Host，要求确切 `401 + edge.unauthorized`。库保留无过期属性的空值 cookie，拒绝 HTTP 源的 Secure、无效 `__Host-`、单标签 Domain，并忽略非法 Max-Age；它没有完整公共后缀列表，仅用于这里固定的 example.com Host，不是通用浏览器 cookie 实现。

顺序：

1. 应急账号登录管理台（Host=`admin.example.com:8084`、实际管理listener8084），登录事务须 completed、实际 `/me` 须 200
2. 将 workspace 策略 `idleMinutes` 调到契约下限 5
3. 签发入网令牌写入 `join/token`，等待节点出现在 `/admin/nodes`
4. 门户登录后 `POST /me/instance/open`，等到实际 `phase=running` 且 `ready`
5. `GET /open/<id>` 换票后访问实例 Host，断言假 DSH 响应（且不用管理台 cookie）。在原单次 HTTP 的 15 秒预算内，仅对 `503 + edge.instance_not_running` 有界重试，以等待实际 phase/Docker 就绪后的 NATS 路由投影；每次请求受剩余预算约束，鉴权失败、未知错误或非实例 HTML 立即失败，截止后仍失败。唤醒阶段同时受原有 480 秒总截止约束
6. 用实例令牌发全 0 心跳；写 `ops-cron/store.json` 闹钟；等待闲置回收与唤醒
   - **闲置成功**须同时成立：闲置窗口开始前，同一实例 jar 的 HTTP 为真实实例页且同一 Docker daemon 返回 `Running=true`；之后实际 `phase=stopped`（**不算**仅 `desired` 变化）、同名容器确实存在且 `Running=false`，同一 jar 经 edge 得到确切 `503 + edge.instance_not_running`。容器 missing、鉴权 401/403、其他错误均失败。真实用户 GET 会推进活动，因此不在闲置截止前追加 GET；停止后的具体路由错误又证明了 cookie 已通过鉴权。只在平台已明确 stopping/stopped 时容忍被拒的尾部假心跳。
   - **唤醒成功**须同时成立：实际 `phase=running` 且 `ready`、容器 `Running=true`，新 `State.StartedAt` 晚于本轮停止观察时刻，且不早于原闹钟减 120 秒预热期（允许 5 秒时钟容差）；到闹钟时刻后 `nextWakeAt` 被消费或前进，再经 edge 取得对应 fixture 的实例页。预热时间和 schedule 消费分别记证据；这不等于证明 DSH 执行了业务闹钟任务。沿用原 480 秒总截止，期间不调用 open 触发唤醒。
7. **双会话吊销**：先完成 A/B 两次登录，再让两者分别取得实例 HTTP + WebSocket。B 先做正向探测，A 紧挨 DELETE 再做同 cookie 的 HTTP 200 与 WS 往返；记录探测、DELETE 发出、关闭时间。B 经 `DELETE /api/iam/v1/me/sessions/{id}` 准确吊销 A；30 秒内 A 传输必须在 DELETE 之后关闭且无独立 DSH Close 帧，旧实例 cookie 的 HTTP 与新 WS 均须 401，A 门户 `/me` 须 401。B 的实例 HTTP、原 WS 往返、门户 `/me` 仍成功，B 会话列表不再列 A 且仍含当前 B。吊销接口须 200/204，**4xx 不算通过**。

任一步失败只打印步骤名、HTTP 状态、实例 phase/desired 等脱敏摘要（不打印 token/cookie/口令）。临时目录与 WebSocket 在结束时清理。

`safeSummary` 在截断前递归处理对象、数组和 JSON 字符串的凭据键，并对文本中的凭据赋值、Bearer 和 JWT 形态值脱敏。`e2e.yml` 在端到端脚本前执行 `node --test e2e/lib/*.test.mjs`，覆盖假阳性拒绝、嵌套脱敏、Cookie 边界、WS 握手/分片/扩展长度/Close 回应和假 DSH 缺失身份头拒绝。假 DSH 的升级始终校验与 HTTP 相同的身份头；普通健康 GET/HEAD 行为不变。

## 节点证书（serverAuth）

workspace NodeCa 签发节点证时带 **clientAuth + serverAuth**（E2）。edge 校验 serverAuth。

**E2 之前入网的旧节点证书缺 serverAuth，必须续期或重新入网，并重启 agent 入口。**

Compose 的 combined 使用 IAM 本地公开 JWKSource，issuer 与共享配置一致为完整 `http://portal.example.com:8080`，不再通过明文回环拉取 JWKS。HTTP-hop另用独立 `iam.crt`/`edge-iam.crt` 与正确 serverAuth/clientAuth、DNS SAN，原节点PKI不替代IAM身份。

fake-ip DNS 会让离线版 OIDC 的 SSRF 校验拒绝保留地址；应调整该 IdP 的 DNS 解析，不关闭校验。外部 IdP 仍依赖网络，细节见 [dsh-plugin.md](dsh-plugin.md#通用-oidc)。此限制不改变旧节点必须续期取得 serverAuth 的要求。

## 相关

设备 WSS 接线：bootstrap 生成 `networkWss.enabled=true`、精确 `/net/v1/ws` 与 `wss://172.29.240.1:18444` 上游；broker WSS 仅绑定该固定网桥网关，NATS TCP 仍绑定 `127.0.0.1:14224`。这与 compose 定义的网桥一致，不使用可能指向其他网桥的 `host.docker.internal:host-gateway`。必须先创建 compose 网桥再启动 host-network broker；就绪依赖沿用 network submit mTLS 健康探针，不能把它当 WSS CONNECT 成功证据。<!-- gitleaks:allow disposable M2 bridge, not a deployment address -->

edge 只读取已有 `network-edge/server-ca.pem`，固定验证 broker SAN `broker.network.internal`；其 Origin 白名单仅取已验证 PortalURL，保留端口并排除 admin。`network-wss-v1-platform-dir` 回执拒绝旧安装配置，原 `network-platform` 私有目录及其权限不变。

**当前 compose profile 只支持 direct HTTP，尚无正式设备 WSS 入口。** 插件只接受 `wss://`；内部上游 WSS 或一次 HTTP Upgrade 101 均不能证明插件正式可用。不得将 `http://portal...` 自动改成 `wss://portal...`，也不得放宽 access 校验或改成明文 WS。最小后续工作是单独实现并审查 compose HTTPS access profile：明确外部 TLS 终止与受信入口、准确域名或 IP SAN 证书和客户端信任、WebSocket 代理与端口映射，再用真实插件执行 IAM 入网及收发。安装配置仍需 IAM 分配 realm 与真实签名链提供的 Ed25519 根；network TLS CA 不能替代它们。

Network 材料与维护见 [部署材料维护](../../deploy/bootstrap/network/README.md)。platform 仅目录挂载独立 `network-platform`（两凭据，生成者 UID/0700，文件0600），保留 Java 安装目录强校验；broker 仅挂载四个所需文件；network/broker 以 uid10001、只读根、丢弃全部能力和 no-new-privileges 运行。prepare 为运行时授予 gid10001 读取权，安装凭据仍仅安装者可读；network 使用额外 gid65533 读取只读服务令牌卷。

Submit 仅监听固定 Compose 网桥网关 `172.29.240.1:18443`，edge upstream 和健康探针使用同一地址；不再监听宿主 LAN 的所有地址。网桥由 compose 的固定 subnet/gateway 创建，必须先存在再启动 host-network runtime。旧 #246 安装的配置回执不适用于此监听地址：prepare 使用新输入版本拒绝复用；M2 是可丢弃测试栈，应保留原材料后在干净测试目录重新 prepare，不能手改 runtime.json 或回执。<!-- gitleaks:allow disposable M2 bridge, not a deployment address -->

Network CA/叶子到期前 30 天产生状态告警；prepare 重入和容器健康探针均检查，过期或损坏使检查失败，不静默续期。运行中可执行 `docker compose --env-file var/compose.env exec -T network /auriga-network-probe --certificates /etc/auriga/network`，监控应每天采集固定告警标签。
