# M2 单机集成（Compose：能给每人起 DSH）

用 Docker Compose 把 platform（iam+org+workspace combined）、edge、NATS、PostgreSQL、节点代理（Docker 驱动）串起来，端到端验证：登录 → 冷启动 → 经 edge 访问实例 → 闲置回收 → 闹钟唤醒 → 双会话吊销。

Windows 侧不假设有 Docker CLI；本机 WSL 的 Linux Docker 或 GitHub Actions（`e2e.yml`）可运行完整栈。使用前先确认连接的是本机 daemon。有 Docker 的 Linux 可按下面步骤本机跑。

## 组件与端口（本机 / CI，host 网络）

| 组件         | 地址                                        | 说明                                                                                                                                  |
| ------------ | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| PostgreSQL   | `127.0.0.1:15432`                           | 库 `auriga`；角色见 `deploy/compose/postgres/init.sql`                                                                                |
| NATS         | `nats://127.0.0.1:4222`                     | JetStream；平台 / 路由写 / edge 会话+路由读                                                                                           |
| 本地镜像仓库 | `127.0.0.1:5000`                            | 推送假 DSH                                                                                                                            |
| platform     | `127.0.0.1:8081` HTTP，`7443` 节点 gRPC/TLS | `combined,dev`                                                                                                                        |
| edge         | `127.0.0.1:8080`                            | `allowLocalIngress=true`；unix 入口                                                                                                   |
| 节点代理     | host 网络 + Docker socket                   | 单机 ingress：`/var/lib/auriga/ingress/ingress.sock`（目录 0750、套接字 0660，组为 edge 的 gid，见 `AURIGA_AGENT_INGRESS_LOCAL_GID`） |

公开仓示例 Host：`portal.example.com` / `admin.example.com` / `<id>.i.example.com`（经 edge，无需真实 DNS，请求带 `Host` 即可）。

## DSH 运行时

默认使用**极简假 DSH**（`deploy/compose/fake-dsh`）：Node HTTP + 最小 WebSocket echo，提供 `/_auriga/health` 与身份头校验，**不是** S4 真实 DSH 离线包，也**没有**真实插件 / Cordis 链路。真实模式需使用下节的 fixture、版本元数据和 `DSH_FIXTURE=real`，不能只换镜像后继续沿用假响应断言或代发心跳。

本验收**不能**解读为「真实 DSH / 真实托管插件已通过」。

## 真实 DSH 与托管插件（W3）

真实模式使用固定Linux镜像、当前renderer实际补丁、独立internal网络、非root uid、只读根和只读meta。它在完整生命周期前直接检查实际Docker加固参数、网络归属及仅实例/受信edge两个成员。验收结果以**对应固定源码与镜像**的脱敏`w3-evidence.json`为准：只有status=passed、rawHeartbeatVerified=true、lifecycleVerified=true全部成立，才能报告该轮真实HTTP交互和生命周期通过。现有E2E M2工作流默认仍验证假DSH；库测试、镜像构建或部分成功都不能替代真实运行，也不能据此声称NAS已部署。

### 构建输入与摘要交付

`real-dsh/versions.json` 记录 S4 分支提交、DSH **0.2.0-rc.2**、Node **22.19.0**、npm **10.9.3**、目标 **Linux amd64 / glibc**。完整 npm v3 锁原样取自 S4，SHA-256：

```text
7568ed6aeb263e8605332578aba9b3b099974bf2b80704afd92cc86b7afc168b
```

构建必须显式提供 `node:22.19.0-bookworm-slim@sha256:<64位摘要>`，脚本拒绝浮动 tag，并要求它与 `versions.json` 的 `nodeImage` 完全相等。该字段记录从 Docker 官方 registry 的固定 tag 解析得到的 Linux amd64 摘要、日期和命令，**独立审查仍为 pending**，来源解析不等于审批。Docker 构建实际核对 Node/npm 版本、锁摘要、每项 npm resolved/integrity，再以 `npm ci --omit=dev --include=optional --ignore-scripts --bin-links=false` 安装目标平台依赖；保留 S4 的可选原生包与执行权限处理。不支持 Alpine/musl 或 arm64。

插件源码只复制 `clients/dsh-plugin/src`、包描述与许可证。仓库已有插件 lock 的开发依赖范围与 package.json 不同步，构建只从该锁派生生产锁：去掉 dev 条目、校验直接生产版本与 package.json 精确相等，保持全部生产包的 resolved/integrity，不重新解析版本。两个锁的摘要均记入 manifest。构建上下文不复制用户 `.dsh`、公司 profile、凭据、模型配置或宿主 node_modules。

`scripts/build-real-dsh.mjs` 先将 Dockerfile 明确需要的源码/锁/元数据复制到临时白名单上下文（约 595 KB），不把根 node_modules、var 或 .git 发给 daemon；构建后清理该临时上下文。推送本地 registry 后从 RepoDigests 取得固定镜像引用，写 `var/real-dsh.json`，其中包括镜像与基础镜像摘要、版本、锁摘要和安装文件摘要清单。这个文件与对应镜像是交给 D0/主控的边界。**本次只取得本机镜像 ID，尚未推 registry 取得 RepoDigest，没有可交付的已验收制品。** 镜像摘要覆盖最终启动器；manifest 不替代发行签名，Compose bootstrap 的 artifact signature 仍是原有 e2e 占位值，不能用于生产验签。

启动入口为 `real-dsh/start.mjs`，使用镜像内 Node 启动原版 DSH `web --patch /run/auriga/cordis.patch.yml --no-open`，即节点代理渲染的补丁（不再带 fixture 自带补丁）。`--patch` 必须放在 web app 的 `--no-open` 参数之前，否则 launcher 会把它透传并报未知参数。DSH 0.2.0-rc.2 的命令行拒绝 `--host 0.0.0.0`，所以监听地址由渲染补丁的 `webserver` 行给出（Docker 运行时 `0.0.0.0`，原生进程 `127.0.0.1`），同一补丁装载 `auriga-dsh/plugin`、写入 `trustedHosts`。原生包、插件与前端均在构建期准备；实例启动不执行 npm/pnpm。

DSH 的模块解析只接受安装/profile manifest 的依赖闭包，单独的安装目录 symlink 不足以装载插件。因此该固定 fixture 启动时物化专属 web profile manifest，只声明镜像中预装的 `auriga-dsh`，并链接到该预装目录；不会下载或安装依赖。它不能代替通用生产插件的安装、启停或用户 profile 合并验收。HOME、DSH_HOME、缓存、临时目录及工作空间都放在 `/home/dsh` 可写挂载中；本机 WSL 验证用 Linux 原生临时目录，Windows 盘挂载显示的 0777 会被 DSH credentials-local 拒绝。运行时使用 agent 分配的非 root uid、只读根文件系统与独立内部网络；补丁关闭原生启动 URL 输出，遥测保持禁用。

### Linux 复现（独占的新 M2 测试栈）

不要在已有数据的环境直接切换 fake/real。以下命令仅供有 Docker 的本地 Linux 测试环境，工人未执行；需预装仓库要求的 Java/Go/Node 工具链。先由主控解决下节接线缺口，再运行：

```bash
cd <auriga-worktree>
export NODE_IMAGE="$(node -p 'require("./deploy/compose/real-dsh/versions.json").nodeImage')"
# versions.json 记录官方 registry 的 linux/amd64 摘要与来源；独立审查仍待完成。
# 此地址必须已通过实例隔离网络的 allow 规则并实测可达；不能用宿主回环地址。
export AURIGA_AGENT_INSTANCE_PLATFORM_URL='http://<实例网络可达的 edge 内部入口>:8080'
export DSH_FIXTURE=real
bash deploy/compose/scripts/prepare.sh
set -a; source deploy/compose/var/compose.env; set +a
docker compose -f deploy/compose/docker-compose.yml --env-file deploy/compose/var/compose.env up -d --build --wait
# platform 首次生成的应急 enrollment 需当前测试用户可读；不要打印内容。
AGENT_VOLUME=/var/lib/auriga \
  ENROLLMENT_FILE=deploy/compose/var/enrollment/emergency-enrollment.json \
  JOIN_TOKEN_FILE=deploy/compose/var/join/token \
  node e2e/m2.mjs
docker compose -f deploy/compose/docker-compose.yml --env-file deploy/compose/var/compose.env down -v
```

`prepare.sh` 在 real 模式自动构建、推送并选用真实模板，模板版本/名称/标签同步变化；默认 fake 行为保留。`var/` 含应急凭据与本地测试私钥，不提交、不贴日志。仅将 `var/real-dsh.json` 和脱敏的 `var/w3-evidence.json` 交给主控；D0 独立处理 NAS 包，不运行任何 NAS 连接命令。

真实模式与 W2V 共用登录、独立 CookieJar、冷启动、实际 phase、Docker Running、edge 和双会话吊销检查，额外要求：

1. 实际容器的镜像引用与构建摘要一致，容器内版本/锁摘要与元数据一致；HTML 必须含真实 DSH boot 注入和 module 入口，假页或普通 200 HTML 不能通过。
2. 直接请求容器（绕开 edge）验证正式插件 health 字段白名单；无签名、错误签名、错主人、过期、重放和未签名健康写请求都必须为 `401 + common.unauthenticated`。正常签名必须取得真实 HTML。
3. real 模式必须指定 `RAW_HEARTBEAT_FILE`，从受控本机观察代理读取实际被 workspace 接受的心跳。先等待门锁正向请求的交互上报落稳，再持续至少65秒只访问免鉴权健康接口，要求每次健康请求都符合真实契约，至少两条实际心跳四计数均为0、health.ok=true、原始lastInteractionAt和平台lastActivityAt均不前进。心跳样本接收时间必须跨至少25秒，末条距窗口结束不超过35秒，防止开头突发请求或停止的发送器假通过。再经edge发真实用户页面请求，要求原始交互时间及平台投影同时前进；随后第二个65秒窗口再次核对实际心跳静态。全部成立后才记录rawHeartbeatVerified=true；这仍是HTTP用户交互验收，尚未覆盖完整浏览器前端操作。real模式不会代发心跳。
4. real 模式禁止脚本代发心跳；真实插件无法报活动则失败。真实闲置回收、闹钟唤醒仍必须分别同时取得 phase / Docker / edge 证据。WS 用 DSH 的 `/api/remote.mux` 原生传输，不要求假 echo；用 masked Pong 保活，并在 DELETE 紧前以唯一随机 Ping/Pong 往返证明传输仍可用。假模式在该位置重新完成文本回声。客户端持续读取控制帧，记录并回复 Close。edge 当前直接切断代理 TCP；若收到 DSH Close 帧、关闭早于或等于 DELETE 发出时间，都不能算吊销通过。

### 本机原始心跳观察

`deploy/compose/scripts/heartbeat-observer.mjs` 仅用于本机Linux测试，在宿主8082监听并转发至回环8081的真实workspace。它不合成请求、不改认证；只有真实workspace返回200才保存白名单字段：接收时间、实例UUID、四计数、交互时间、健康布尔值与版本。认证令牌只在内存原样转发，未知字段、health.problems和所有请求头都不落盘。报文最多64KiB，输出文件0600、必须是新文件，单次最多10000条。

在 `prepare.sh` 之后、启动edge之前，把**本次生成配置**的 workspace 上游改到观察端口，然后运行观察进程：

```bash
cd deploy/compose
node --input-type=module -e 'import fs from "node:fs"; const p="var/edge.config.json"; const c=JSON.parse(fs.readFileSync(p)); c.upstreams.workspace="http://host.docker.internal:8082"; fs.writeFileSync(p,JSON.stringify(c,null,2),{mode:0o644});'
export RAW_HEARTBEAT_FILE="$PWD/var/raw-heartbeats.jsonl"
node scripts/heartbeat-observer.mjs &
OBSERVER_PID=$!
trap 'kill "$OBSERVER_PID" 2>/dev/null || true' EXIT
docker compose --env-file var/compose.env up -d
cd ../..
DSH_FIXTURE=real node e2e/m2.mjs
```

应在独立测试机运行，避免宿主8081/8082被其它服务占用；NAS配置不使用这个观察代理。输出与`w3-evidence.json`都是脱敏验收证据，原始var凭据文件不交付。生命周期所有严格检查结束后才将lifecycleVerified置true，任何提前失败都保留false。

失败也会写 `var/w3-evidence.json`（状态 failed、已取得的步骤、失败步骤）；缺失的证据不视为成功。HTTP 请求有 15 秒超时，异常退出清理本脚本的临时目录与 WS。脚本不自动清除实例数据或关闭外部测试栈，操作人负责按上面的 down 命令清理。

### 节点代理接线（第 2 轮已修）

- **插件平台地址**：`AURIGA_PLATFORM_URL` 不再取 gRPC 控制地址。节点代理读 `AURIGA_AGENT_INSTANCE_PLATFORM_URL`（`http(s)://主机[:端口]`，实例内部网络可达的 edge 内部入口；允许 HTTP 以支持只有 IP/HTTP 的部署），未设置时渲染为空并告警，托管插件拒绝启动而不是把令牌发往控制地址。Compose 透传同名变量，CI 的 fake 模式不设（假 DSH 不发心跳）；real 模式需要操作人给出容器网络可达的地址，**本机未验证可达性**。
- **cordis.patch.yml 形状**：渲染为 DSH Loader 补丁列表：`insert` 新增 `auriga-dsh`（`auriga-dsh/plugin`，注入 webServer/connection）和每个团队 MCP 的 `@deepseek-ai/dsh-mcp-client` 行（`Authorization` 用 `!!js` 在求值时读令牌文件，令牌值不进 YAML）；`webserver` 行给监听地址/端口；`web-runtime` 行关闭 URL 输出并写 `trustedHosts`。规格补丁 `plugins.<行 id>.<键…>` 写进对应行的 config（Loader 语义：整行 config 替换，不深合并）；`webserver`、`web-runtime`、`connection`、`auriga-mcp-*` 与插件的 `trustedHosts` 由代理独占，规格补丁不能改。团队模型应写入用户设置文档中带平台标记的条目，renderer 尚未实现，遇到 `model_providers` 直接失败，不再输出 DSH 不认识的映射。
- **trustedHosts**：节点代理读 `AURIGA_AGENT_INSTANCE_PARENT_DOMAIN`（与 edge `instanceParentDomain` 相同，Compose 为 `i.example.com`），写入 `<实例 id>.<域>`。节点 ingress 会把 Host 改成实例上游地址（IP 字面量），DSH 原生 Host 栅栏靠绑定地址推导的 IP 放行；浏览器 Origin 是 edge 实例域名，所以由插件对门锁放行的请求按这份 `trustedHosts` 校验 Origin / `Sec-Fetch-Site`（见 dsh-plugin.md）。
- **`/api/remote.mux`**：edge 对实例域名不做路径白名单，升级只要求 Origin 等于实例域名；已补 edge 回归测试证明该路径的升级被转发、身份头 `htu` 绑定该路径、跨站 Origin 被拒，无需改 edge 代码。

### 仍需主控处理

- `contracts/openapi/workspace.yaml` 的 `HeartbeatRequest.activity`、生成模型与 `WorkspaceService.heartbeat` / `Lifecycle`：协议需表达未知（建议四个计数改为可空或增加 `unknown: [字段名]`），平台对未知视为"不可回收但刷新 plugin_seen_at"，并读取 `health.ok`。在此之前插件遇未知仍暂缓心跳（并按字段名记一条告警日志）。纯 DSH 没有 IM 服务：由模板规格补丁 `plugins.auriga-dsh.imBots = "none"` 显式声明后按已知 0 上报；没有声明时仍为未知，IM 服务存在但读取失败也仍为未知。
- 真实镜像、原生依赖启动、用户操作、回收/唤醒和 WS 吊销仍需在有 Docker 的 Linux 上实际执行；不能用已有 S4 离线启动或 W2V 假 DSH 结果替代。

## 端到端脚本（`e2e/m2.mjs`）严格验证了什么

Cookie：管理台 / 门户 / 实例各用独立 jar，按 Set-Cookie 的 host、Domain、Path、Max-Age/Expires 选择。除 jar 选择单测外，脚本还将实际门户、管理台会话 cookie 手动发给实例 Host，要求确切 `401 + edge.unauthorized`。库保留无过期属性的空值 cookie，拒绝 HTTP 源的 Secure、无效 `__Host-`、单标签 Domain，并忽略非法 Max-Age；它没有完整公共后缀列表，仅用于这里固定的 example.com Host，不是通用浏览器 cookie 实现。

顺序：

1. 应急账号登录管理台（Host=`admin.example.com`），登录事务须 completed、实际 `/me` 须 200
2. 将 workspace 策略 `idleMinutes` 调到契约下限 5
3. 签发入网令牌写入 `join/token`，等待节点出现在 `/admin/nodes`
4. 门户登录后 `POST /me/instance/open`，等到实际 `phase=running` 且 `ready`
5. `GET /open/<id>` 换票后访问实例 Host，断言假 DSH 响应（且不用管理台 cookie）。在原单次 HTTP 的 15 秒预算内，仅对 `503 + edge.instance_not_running` 有界重试，以等待实际 phase/Docker 就绪后的 NATS 路由投影；每次请求受剩余预算约束，鉴权失败、未知错误或非实例 HTML 立即失败，截止后仍失败。唤醒阶段同时受原有 480 秒总截止约束
6. 用实例令牌发全 0 心跳；写 `ops-cron/store.json` 闹钟；等待闲置回收与唤醒
   - **闲置成功**须同时成立：闲置窗口开始前，同一实例 jar 的 HTTP 为真实实例页且同一 Docker daemon 返回 `Running=true`；之后实际 `phase=stopped`（**不算**仅 `desired` 变化）、同名容器确实存在且 `Running=false`，同一 jar 经 edge 得到确切 `503 + edge.instance_not_running`。容器 missing、鉴权 401/403、其他错误均失败。真实用户 GET 会推进活动，因此不在闲置截止前追加 GET；停止后的具体路由错误又证明了 cookie 已通过鉴权。只在平台已明确 stopping/stopped 时容忍被拒的尾部假心跳。
   - **唤醒成功**须同时成立：实际 `phase=running` 且 `ready`、容器 `Running=true`，新 `State.StartedAt` 晚于本轮停止观察时刻，且不早于原闹钟减 120 秒预热期（允许 5 秒时钟容差）；到闹钟时刻后 `nextWakeAt` 被消费或前进，再经 edge 取得对应 fixture 的实例页。预热时间和 schedule 消费分别记证据；这不等于证明 DSH 执行了业务闹钟任务。沿用原 480 秒总截止，期间不调用 open 触发唤醒。
7. **双会话吊销**：先完成 A/B 两次登录，再让两者分别取得实例 HTTP + WebSocket。B 先做正向探测，A 紧挨 DELETE 再做同 cookie 的 HTTP 200 与 WS 往返；记录探测、DELETE 发出、关闭时间。B 经 `DELETE /api/iam/v1/me/sessions/{id}` 准确吊销 A；30 秒内 A 传输必须在 DELETE 之后关闭且无独立 DSH Close 帧，旧实例 cookie 的 HTTP 与新 WS 均须 401，A 门户 `/me` 须 401。B 的实例 HTTP、原 WS 往返、门户 `/me` 仍成功，B 会话列表不再列 A 且仍含当前 B。吊销接口须 200/204，**4xx 不算通过**。

任一步失败只打印步骤名、HTTP 状态、实例 phase/desired 等脱敏摘要（不打印 token/cookie/口令）。临时目录与 WebSocket 在结束时清理。

`safeSummary` 在截断前递归处理对象、数组和 JSON 字符串的凭据键，并对文本中的凭据赋值、Bearer 和 JWT 形态值脱敏。`e2e.yml` 在端到端脚本前执行 `node --test e2e/lib/*.test.mjs`，覆盖假阳性拒绝、嵌套脱敏、Cookie 边界、WS 握手/分片/扩展长度/Close 回应和假 DSH 缺失身份头拒绝。假 DSH 的升级始终校验与 HTTP 相同的身份头；普通健康 GET/HEAD 行为不变。

## 节点证书（serverAuth）

workspace NodeCa 签发节点证时带 **clientAuth + serverAuth**（E2）。edge 校验 serverAuth。

**E2 之前入网的旧节点证书缺 serverAuth，必须续期或重新入网，并重启 agent 入口。**

Compose 里 platform 的 `AURIGA_IAM_JWK_SET_URI` 指向 `http://127.0.0.1:8081/oauth2/jwks`：`issuer` 仍是虚拟 Host，资源服务器必须经 loopback 拉 JWKS。

fake-ip DNS 会让离线版 OIDC 的 SSRF 校验拒绝保留地址；应调整该 IdP 的 DNS 解析，不关闭校验。外部 IdP 仍依赖网络，细节见 [dsh-plugin.md](dsh-plugin.md#通用-oidc)。此限制不改变旧节点必须续期取得 serverAuth 的要求。

## 已知限制

| 项          | 说明                                                                 |
| ----------- | -------------------------------------------------------------------- |
| 假 DSH      | 无真实插件 / Cordis；心跳由 e2e 代发；WS 仅为吊销回声                |
| 闲置下限    | 契约 `idleMinutes` ≥ 5，整段 e2e 约需 10+ 分钟（适配 30 分钟工作流） |
| host 网络   | Compose 为单机设计；多机需改 ingress TCP + 通告地址                  |
| 凭据        | `deploy/compose` 内口令仅为 e2e 占位，禁止用于生产                   |
| 本机 Docker | Windows 侧无 CLI 时可用已核实本机 daemon 的 WSL；库级测试无需 Docker |
