# 管理台邀请与分组

管理台使用现有 Vue 3、Element Plus 与 shared API client。入口位于“成员与权限 → 邀请 / 分组”，不新增共享认证或权限契约。

## 邀请

- `GET /api/org/v1/admin/invitations` 按状态与服务端不透明游标分页；需要 `org.invitations.read`。
- 创建、撤销需要 `org.invitations.write`。确认提交前重新查询 `/api/org/v1/me`；服务端仍为最终权限判断依据。
- 本页只创建普通成员邀请：`memberType=member`、`maxUses=1`，`roleIds/groupIds/providerIds` 显式为空。没有附加角色或分组，身份源不限制；可选限定邮箱和显示名。省略 `expiresAt`，采用服务端当前七天默认值。页面会说明上述范围，不自动发送邮件。
- 创建成功只在当前组件内存保存正式返回的 code 和 url；不放入路由/日志/localStorage/sessionStorage/列表或全局状态。链接按服务器原文展示和显式复制，不从管理台 location、Host 或 code 拼出门户地址。结果用可选择的文本呈现，不作为 HTML 或可点击链接注入；仅接受绝对 HTTP/HTTPS URL，不限制正式域名、IPv4 端口或路径前缀。
- 后端 INVITELINK1 已使用唯一且 tenant 匹配的受信 DeploymentAccess 生成 url；缺来源在写前 503。页面提示检查受信门户配置与服务状态，不展示占位链接或假称已创建。非法创建响应不伪造成功，提示先检查列表而非重复创建。
- 关闭结果、主动刷新、筛选、新建、撤销、撤读权/401 或离开页面会集中清除 code/url。创建和复制以结果代次隔离，晚到响应不能恢复已清除结果或复制提示。已复制的系统剪贴板不能由网页自动撤回。
- 创建成功但列表读回失败时保留一次性链接/code，并提示“操作已提交，但刷新失败”；“重试”仅重新读取列表且保留结果，不重放 POST。此重读若发现撤权或 401/403 会清除结果。主动“刷新”仍遵循清理语义。

## 分组

- 分组列表与详情、成员列表需要 `org.groups.read`；创建、修改、删除、加入/移出成员需要 `org.groups.write`。
- 加入成员额外要求 `org.members.read`，候选来自已有成员搜索与游标列表，不接受任意账号 ID 文本输入。组成员分页独立保留游标，切换分组即清除旧候选与旧响应。
- 手动分组支持名称、描述和父组；映射分组本页仅查看。修改使用 `application/merge-patch+json`。
- 父组选项来自当前真实组列表，排除自身和当前已知后代。已有父组不能清空：契约未定义 `parentId:null`，现有后端也会将 null 当作保留旧父组。前端不发送契约外的清除值。
- 删除前说明：成员关联、该组角色绑定与配额将删除；有子组时服务端以 `org.group_not_empty` 拒绝。加入组的授予上限由服务端以 `org.grant_exceeds_own` 等校验。
- 后端现有 `updateGroup` 显式拒绝自身作为父组，尚未发现完整的多级循环防护。前端过滤不是服务端安全保证，无法防止并发重设父组或直接 API 调用；需后续后端任务补完整循环校验和事务测试。本批没有修改服务端或扩大权限。
- 写入成功后的读取失败会提示重新读取，避免把刷新失败当成写入失败后重复操作。组编辑 API 没有本批可用的版本字段/ETag，不能宣称已防止多个管理员覆盖彼此修改。

## 配额

“成员与权限 → 配额”调用现有 Org 默认、组覆盖、成员覆盖 GET/PUT/DELETE 和成员 effective 接口。读取需 `org.quotas.read`，写入需 `org.quotas.write`，最终确认时重查。组/成员目标只能从具有 `org.groups.read` / `org.members.read` 权限的真实候选中选取；配额权限不授予候选读取能力。成员候选支持搜索与不透明游标分页。

- PUT 替换本层整份配置，确认中列出本次清除的已知字段。未编辑的字段沿用读回值，未知字段保持读回内容；没有把 PUT 当成 PATCH。
- 省略为“本层未设置”。只有 maxInstances、monthlyBudgetMicros、dailyTokens 提供 null“不限”。0 是明确数值，alwaysOnAllowed 则区分未设置/允许/禁止。CPU/内存/磁盘不提供 null。默认层没有删除按钮；组/成员可确认删除整层覆盖。
- 输入整数必须满足契约最小值且为 JavaScript 安全整数；单位分别为 CPU 毫核、内存 MB、磁盘 GB、实例个数、百万分之一货币单位、token。月预算币种为三位大写，遵循部署币种；不要求每个覆盖层重复设置 currency。
- 读回任何已知或未知数值超出安全整数范围时，页面明确禁止本层保存，避免将 JSON 解析后失真的数值写回。有效配额的超范围数值也标为无法精确显示。精确大整数的通用消费能力仍需独立契约/客户端协调，本批不改 shared。
- 仅将当前配额 GET 的 `org.not_found` 404、且再次正式查询目标仍存在的情形解释为本层未配置。默认层 404、目标 GET 404、其他错误码 404、有效配额 404 均保留错误。前端复核不能替代后端事务中校验目标存在性。
- 成员有效值完全来自正式 effective 接口，保存/删除后重新读取；缺失字段显示未设置，不推算为无限。不猜具体来源组，只说明成员覆盖 → 多组最宽松值 → 默认的通用逐字段顺序。组或默认层没有伪造单个“成员有效值”。
- 保存不承诺清空在途模型预占、即时变更现有实例或防止多管理员覆盖。写成功但刷新失败时提示只重试读取，不重放写入。

读权撤销后，邀请和分组主列表也会清空；原错误提示和凭据/详情/候选的清理仍保留。

## 角色与授权

“成员与权限 → 角色”读取正式角色列表、详情与权限目录，需要 `org.roles.read`。定义创建/修改/删除需要 `org.roles.write`；绑定授予/撤销独立需要 `org.roles.grant`。确认前重查 `/org/v1/me`，任一权限不隐含另一项，失去读取能力会清角色、权限、表单、绑定和候选。

- 内置角色依据正式 `builtin` 标记只读，不按角色名称推断权限。自定义角色 key 仅创建可编辑；PATCH 按当前契约携带原 key，后端不修改它。请求不发送 builtin/adminOnly 等服务端字段。
- 权限项来自 `/admin/permissions`；编辑器只能新增本人当前持有的目录权限，已读回的已有选择保持可见，不静默丢弃。服务端 `org.grant_exceeds_own` 是最终授予上限，页面不将过滤当作后端安全保证。确认会列出权限及目录标注的敏感项。目录失败时禁止创建/编辑和新增绑定，允许重试读取。
- LocalizedText 是生成类型；当前 Org 服务实际保存/返回 en、zh 两个键。页面以 en/zh 提交中英文，英文名称非空；空描述提交 `{en:"",zh:""}`。这会写入空字符串，不宣称清成数据库 NULL；不编辑其他语言标签。
- 角色删除会级联删除该角色的成员、分组及服务账号绑定，确认框明确说明；页面不把角色写权限当作一般绑定管理权。
- 绑定列表按所选 roleId 读取并保存不透明游标。创建仅支持正式成员/分组候选，分别要求 `org.members.read` / `org.groups.read`；成员候选有搜索和分页，无任意 UUID 输入。最终写前再次查询所选角色和目标存在性，并复核目标读取权限。现有绑定的撤销使用正式绑定 ID 与 grant 权限，不要求额外读取未选候选。
- 本批没有服务账号权威候选接口，故只显示已有服务账号绑定，不创建或撤销它们。成员/分组绑定的 last_owner、跨租户和授予上限仍由后端验证。
- 写入成功但正式列表/详情/绑定读回失败时单独提示“只重试读取”，不自动重放写入。没有 ETag 的编辑不能保证多个管理员不会互相覆盖。客户端存在性复核不能保证后端事务中的目标存在与并发安全；接口缺口交主控单独协调。

## 验证边界

在仓库根按 `docs/dev/web.md` 设置环境后，运行 `pnpm --filter @auriga/admin lint`、`typecheck`、`test`、`build`。组件与请求测试覆盖确认取消、加载/空态/错误、撤权、敏感值清除、不透明分页、选项失败及恢复。测试保留真实 Element Plus Teleport；统一替换 Teleport 会使此版本的 Select 递归更新。

shared 的旧开发 mock 没有覆盖本批全部管理端点，组件测试在 fetch 边界使用脱敏响应。真实浏览器验收应连接主控批准的测试后端，分别验证域名/IP 管理入口、CSRF、登录失效和服务端拒绝；本地组件通过不代表部署验收完成。
