# 连接模式：本地 owner 与可选平台登录

R2 统一使用 DSH 的主人认证。桌面窗口和持有有效 DSH 主人凭据的浏览器具有相同的本地权限。

## 本地访问

DSH 原连接服务先验证请求，插件只接受 principal.kind=owner。伪原生头、未认证请求、非 owner 不取得本地主人权限。平台未配置、未登录、不可达、过期或退出，不再影响本地 API、WebSocket、会话、模型、工具与设置。插件不把本地 HTTP/WS 绑定到平台会话寿命，启动不强制跳转登录。

连接模式不提供插件本地应急账号或平台应急账号；standalone 原有逻辑不变。

## 平台登录

登录只提供团队账号，沿已有 nativeConnect、PKCE、device_code、口令和 TOTP 流程。平台身份保存在后端，同一 DSH 的 owner 窗口共享，令牌不返回页面。HTTP 平台操作继续校验同源与 CSRF，原生 RPC 继续校验 DSH 准入和固定输入。

登录是 Auriga 面板或设置中的主动操作。登录页始终有“跳过”；不可达时显示“总部不可达”。跳过立即返回 DSH，启动脚本不反复提示。退出保留已有确认页。

配置可离线加载，后台尝试用保存的刷新令牌恢复平台能力。刷新前先做只读可达性检查，明确未建立连接的错误可重试；旋转令牌请求结果不明时保留防重放栅栏，要求重新登录。失败只撤销平台能力。

## 设置状态

一个状态卡，桌面依次显示平台、账号、消息网络；诊断默认折叠，登录和退出互斥。托管模式隐藏地址编辑、连接测试及登录/退出，读取实例 owner 身份与托管网络状态。

姓名、设备名、登录时间、网络和模型状态只采用实际取得的数据。凭据未提供姓名时显示成员 ID 并说明原因。网络 READY 不代表模型中转站可用。

## 安装版验收

e2e/phase1/desktop-offline.mjs 参数依次为私有 fixture 目录、生产插件 tgz、新建的 e2e/target 子目录。工具启动实际安装的 Electron，使用独立断网测试插件及本地模型 HTTP fixture；凭据只读，不进入公开报告。

断网插件源为 desktop-offline-isolation.mjs，通过标准 DSH bundle 安装；配置只有测试切换文件与目标地址。启用标记必须实际出现，还须观察网络断开和恢复。它不进入生产包、不修改系统网络。真实截图、READY、恢复及日常更新是否通过，以本次工位报告及原始证据为准，单测不能代替现场验收。
