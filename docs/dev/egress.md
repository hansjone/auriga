# 托管实例的公网模型出口

云端 DSH 继续只接入自己的 `internal` 网络。可信 edge 和独立 egress 服务各接入这张网；实例不加入控制网络、共享外网 bridge 或宿主网络，实例之间没有新增通道。

egress 只提供公网目标的 `CONNECT host:443`。它不解密 TLS，不读取、记录或保存提供商 Key。环回、私网、链路本地、metadata、文档/测试/fake-IP 和特殊翻译地址均拒绝；DNS 所有回答都通过检查后，只拨号已检查的数字地址，避免第二次解析造成重绑定。可信部署材料给出的门户和管理台主机及其子域，也在 DNS 查询前拒绝，即使这些域名能解析到公网。客户端仍按原生方式验证提供商证书。

公开 Compose 与 NAS 配方都用同一 edge 镜像中的 `/auriga-egress`，以独立非 root、只读、无额外能力的服务运行，只接入自己的外网 bridge，既不发布宿主端口，也不挂载配置、秘密或 Docker socket。agent 核对同一实际镜像 ID、项目和角色、精确启动参数、进程生命周期、别名及隔离设置，才将它接入本人实例网。出口重建丢端点时，既有协调恢复该受信端点；健康只读检查不偷偷改网络。

模板使用已有 `Network.egress_proxy` 指定 `http://auriga-egress.internal:3128`。DSH 公开 rc.3 launcher 根据 `HTTP_PROXY`/`HTTPS_PROXY` 安装原生代理，原生 DeepSeek、普通 `fetch` 和采用该传输的 SDK 通过它出网，不需要修改 DSH。`NO_PROXY` 保留安装材料里已验证的平台、门户、模型与身份发行域名，使团队内部请求继续直接走受信 bridge。

正常安装运行原公开 `start` 流程即可；已有实例在管理台正常更新运行时（或对当前默认版本重新应用）后，模板中的网络设置会进入新规格并按已有重启路径生效。只更新镜像而不更新实例规格，不会自动改写旧实例的环境。

如果宿主的分流 DNS 返回 fake-IP，可在 egress 服务环境设置 `AURIGA_EGRESS_DNS_SERVER=192.0.2.53:53`（示例地址，替换为管理员核实的 DNS 端点）。该配置仅影响 egress，接受受信管理员指定的公网或内网数字 DNS 端点，不改变 NAS、其他容器、路由器或系统 DNS；指定后失败不会回退到环境 DNS。请求目标仍严格拒绝私网及 fake-IP。DNS 返回公网地址也不能单独证明解析正确，应再以保留原域名/SNI、正常证书验证的 HTTPS 调用核实。

连接建立最多十秒，空闲五分钟或总时长三十分钟后结束；进程停止会关闭包括 hijack 在内的隧道。TLS 双向复制保留 CONNECT 后已缓冲的字节，支持 TCP 半关闭。以上是传输生命周期边界，不改写模型上下文、输出参数或用户压缩策略。

当前出口仅支持 HTTPS 的 CONNECT 443。没有实现 org 分类白名单下发、HTTP 80 正向代理、任意私网供应商访问或每实例独立出口计费。普通子进程是否采用代理仍取决于其自己的传输；例如 Node 22.19 的子进程原生 `fetch` 不因存在环境变量而自动使用代理，不能把 DSH 主进程通过冒称所有工具都已联网。
