# 插件资源面板与集成边界

## 当前实现

`web/panel` 是既有 `auriga-team-panel` 自包含 Web Component。资源市场与我的资源使用同一个组件，中英文文案及明暗主题齐全，优先继承 DSH 的 `--dsw-alias-*` 主题变量。设置没有成为第三个资源页签。

资源市场的只读客户端消费现有 resource OpenAPI：包列表、包详情、版本列表；显示名称、作者 ID、资源级别、总部可用状态、默认版本 ID、版本及发布状态。搜索只过滤已加载结果，接口只传现有 `limit/cursor`，不发明服务端搜索参数。版本按接口返回顺序显示，不用版本字符串推断最新安全版本。不会执行资源内容或解释摘要为验签成功。

请求只能经过宿主 `context.fetch`，不读取令牌、不调用 `apiBase`、不回退到全局 fetch、不存浏览器资源缓存。只接受 `connect` / protocol 1 且有宿主 transport 的上下文。受保护面板的签名/SRI加载逻辑未修改；managed 模式按 ADR0021 保持零资源API请求。

读取失败区分未登录、无权限、入口不存在、限流、服务不可达及无效数据；不显示后端原始错误正文。15秒超时，导航、卸载和连接切换中止请求并忽略迟到结果。读取失败清除已显示内容，不把旧市场数据作为离线回退；401通过既有 `auriga-auth-required` 事件通知宿主。刷新及重试由用户明确触发，无自动重试循环。

**当前主线没有 resource 运行期实现，connect 仍为占位。本批是可接线的只读UI，不是已完成的真实资源集成。** 生产代码没有测试资源、模拟连接状态、固定成功响应或安装假进度。没有宿主连接时显示不可用；已有托管实例同样不能展示真实市场。组件测试中的 fixture 仅证明界面逻辑，不能当作端到端验收。

## 安装、启停与配置

`Package.enabled` 只表示总部资源是否可用，不表示实例插件正在运行。`Distribution.state` 只表示一次分发请求，不能替代安装清单。当前契约没有权威安装清单与插件配置接口，因此所有资源的本机安装状态标为“无法读取”，“我的资源”明确说明缺口，界面没有可执行的安装、启停或保存配置按钮。

正式闭环仍需 R1/WR1/AR1/E3 实现资源ACL、分发、节点实际应用与状态读回，沿用资源发行/撤销/降级签名、下载授权、反回滚与隔离规则。不得将 HTTP 接受响应、下载完成或签名字段存在显示为已安装。

## 下一批 R1a：最小只读后端任务提案

主控可单独派发，目标为真实 PostgreSQL 上的资源元数据读取，不扩大为上传、下载或执行：

1. 路径范围：`services/resource/api/**`、`services/resource/impl/**`，含新 `db/resource/V...` 迁移与测试。平台装配/其他服务API依赖如有需要先列明；契约与公共组件只读，不临时跨schema查询组织表。
2. 依照现有 Package/Version schema 建模，使用 tenant_id、UUIDv7、timestamptz、RLS和运行角色隔离。版本不可变内容身份需保留 digest、sizeBytes、mediaType、revision及现有发布状态字段。测试数据只在测试事务中创建，不加生产演示seed或伪上传。
3. 实现四个现有GET：`/api/resource/v1/packages`、`/packages/{packageId}`、`/packages/{packageId}/versions`、`/packages/{packageId}/versions/{versionId}`。列表参数仅 limit/cursor；沿 common Problem、现有resource权限目录与tenant/owner/group/level规则，不新增错误码或权限key。服务端受信身份解析与组织API只能使用已经实现的公共接口；不足时列为主控依赖，不回退为全租户可见。
4. 分页采用确定性排序和keyset游标；权限过滤在分页前完成，游标须校验并绑定租户/调用者/查询上下文，避免跨用户复用泄漏；按既有错误定义拒绝非法游标。包详情与版本接口必须同等执行ACL，版本ID必须属于路径中的包；不可只保护列表。
5. 用实际嵌入式PostgreSQL验证租户RLS、private owner、群组可见性、成员撤权、不可见包与版本、跨包版本、禁用与撤回/未发布资源的既有可见规则。分别使用至少两个租户/owner，并以既有错误码断言拒绝结果。固定排序下验证分页无漏项/重复，非法游标与越权重放被拒；不mock数据库。
6. 验收如实区分业务控制器HTTP＋真实PG测试和面板端到端。即使R1a通过，当前托管面板仍禁止桥接，P3未实现前也不能宣称插件市场已联通。

## 需主控先定的接口与产品决定

- **资源访问身份**：本批不新增 managed 成员桥接，不改设备 resource audience。未来最小桥接需要先做独立契约/威胁评审，明确允许操作、实例/owner/tenant绑定、撤销、Origin与CSRF；不得泛代理成员API。涉及 `contracts/plugin/**`、IAM/edge及插件服务端，须协调保护路径审查。
- **安装清单**：需正式契约提供实例期望与实际插件状态、版本、generation/observedGeneration、更新时间与分发关联。由服务端验证实例所属，不从浏览器存储或市场包信息推断。
- **配置**：需正式契约定义允许配置schema、只写秘密、脱敏读回、revision前置条件、受保护键及重载反馈。总部包元数据PATCH不能替代实例配置。设置UI将进入宿主设置槽，不直接写DSH配置文件。
- **URL＋Key与设备授权**：设计原型提出URL＋Key，当前连接协议采用设备授权。这是明确待决项；本批不收集Key、不新增认证协议。
- **后续产品能力仍保留**：云端与现场共用一个插件和界面，面板独立更新；本地已安装资源目标由当前DSH读取，不能永久依赖在线市场才能显示。当前仅资源中心plugin契约，不伪造Skills/工具条目或更新状态。程序缓存与资源市场缓存是不同边界；保留可用程序不得绕过既有面板签名/过期规则，受管资源仍受撤销和离线有效期约束。账号、安全设置保留原宿主归属，不因将来新增连接表单而删除。

## 集中验证

在仓库根按既有开发环境配置运行：

```sh
pnpm --filter @auriga/panel test
pnpm --filter @auriga/panel typecheck
pnpm --filter @auriga/panel lint
pnpm --filter @auriga/panel build
pnpm --filter @auriga/panel test:bundle
```

无新增依赖、契约生成变更或部署测试。真实演示最终应使用本机隔离环境及真实服务：认证列表→版本详情→授权实例分发→节点验签与实际应用→权威安装状态→禁用/启用读回，同时验证越权和坏签名拒绝；本批尚未达到这一门槛。
