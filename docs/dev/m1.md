# M1 单机集成（登录与管理台）

把 ctl（PostgreSQL + NATS）、platform-app（iam+org 同进程）和 edge 串起来，跑通应急账号 / 团队账号登录与管理台基本操作。前端默认走真 API（不要设 `VITE_AURIGA_MOCK=1`）。

## 端口与主机（示例）

| 组件 | 默认 | 说明 |
|---|---|---|
| PostgreSQL | `127.0.0.1:15433` | ctl；库 `auriga` |
| NATS | `nats://127.0.0.1:14222` | ctl；JetStream |
| platform-app | `127.0.0.1:8081` | HTTP；gRPC 默认随机或配置 |
| edge | `127.0.0.1:8080` | 对外入口 |
| 门户 Host | `portal.example.com` | 映射到 edge 或本机 hosts |
| 管理台 Host | `admin.example.com` | 与门户不同源 |

公开仓示例一律用 `example.com` / `192.0.2.x`。本机可用 `127.0.0.1` 作 Host（combined 配置已登记 portal audience）。

## 一键数据面

```powershell
. D:\project\chatgpt\.agents\auriga-env.ps1   # 派活环境
Set-Location infra
go run ./ctl start --data-dir ../.dev
go run ./ctl status --data-dir ../.dev
```

凭据：`.dev/credentials.env`、`.dev/service-roles.json`（**勿提交、勿贴日志**）。

从 `service-roles.json` 取 `iam` / `org` 的 JDBC URL 与口令，例如：

`jdbc:postgresql://127.0.0.1:15433/auriga?user=auriga_iam`（口令在 JSON 的 `roles.iam.password`）。

## 启动 platform-app（combined）

先生成 32 字节加密钥（Base64）并导出环境变量：

```powershell
# 密码学安全随机；密钥需持久保存（例如写入 .dev/credentials.env），重启换钥会导致库内签名钥无法解密
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$env:AURIGA_IAM_ENCRYPTION_KEY = [Convert]::ToBase64String($bytes)
$roles = Get-Content .dev/service-roles.json | ConvertFrom-Json
$env:AURIGA_IAM_JDBC_URL = "jdbc:postgresql://127.0.0.1:$($roles.port)/auriga"
$env:AURIGA_IAM_DB_USER = $roles.roles.iam.user
$env:AURIGA_IAM_DB_PASSWORD = $roles.roles.iam.password
$env:AURIGA_ORG_JDBC_URL = $env:AURIGA_IAM_JDBC_URL
$env:AURIGA_ORG_DB_USER = $roles.roles.org.user
$env:AURIGA_ORG_DB_PASSWORD = $roles.roles.org.password
# ctl 生成 .dev/nats.env（NATS_USER / NATS_PASSWORD）；拼进 URL（勿把口令提交进仓）
$natsUser = ((Get-Content .dev/nats.env) | Where-Object { $_ -like 'NATS_USER=*' }) -replace '^NATS_USER=',''
$natsPass = ((Get-Content .dev/nats.env) | Where-Object { $_ -like 'NATS_PASSWORD=*' }) -replace '^NATS_PASSWORD=',''
$env:AURIGA_NATS_URL = "nats://${natsUser}:${natsPass}@127.0.0.1:14222"
$env:AURIGA_IAM_ISSUER = "http://portal.example.com"
$env:AURIGA_PLATFORM_PORT = "8081"
$env:AURIGA_ENROLLMENT_FILE = (Resolve-Path .dev).Path + "\emergency-enrollment.json"

./mvnw.cmd -pl services/platform-app -am -DskipTests package
# combined = 安全默认；dev = 种子 / 明文 JWKS / cookie 不强制 Secure（仅本机）
java -jar services/platform-app/target/platform-app-0.1.0-SNAPSHOT-exec.jar --spring.profiles.active=combined,dev
```

种子（仅 `dev` profile：`auriga.platform.seed=true`）：

1. 发布并激活 IAM 签名密钥（回拨 `publishedAt`，**不**推进共享时钟）
2. 创建应急账号 → 先建仅当前用户可读写的 enrollment 文件再写入凭据（**不打日志**）
3. 创建默认 `team-account` Provider（`invite_only`，`rpId`/`origins` 可配）

重复启动：已有 enrollment 文件则跳过应急安装；已有 team-account 则跳过创建。

## 启动 edge

准备身份头签名 JWKS 文件（含 `d` 私钥，见 [edge.md](edge.md)），示例配置：

```json
{
  "listen": "127.0.0.1:8080",
  "portalHost": "portal.example.com",
  "adminHost": "admin.example.com",
  "instanceParentDomain": "i.example.com",
  "secureCookies": false,
  "trustedProxies": ["127.0.0.1"],
  "upstreams": {
    "iam": "http://127.0.0.1:8081",
    "org": "http://127.0.0.1:8081",
    "workspace": "http://127.0.0.1:8081"
  },
  "static": {
    "portalRoot": "web/portal/dist",
    "adminRoot": "web/admin/dist"
  },
  "tls": { "mode": "off" },
  "rateLimit": { "requestsPerSecond": 50, "burst": 100 },
  "identityKeysFile": ".dev/identity-signing-keys.json",
  "sessionStore": "nats",
  "natsUrl": "nats://127.0.0.1:14222"
}
```

```powershell
Set-Location infra\edge
go run . -config ..\..\..\path\to\edge.config.json
```

`sessionStore=nats` 时 edge 读 `auriga-sessions` KV，并订阅 `auriga.evt.identity.session_revoked` 以断开长连接。iam 在配置了 NATS 时会双写会话 KV。NATS 不可用时 edge 回退 memory（本机直连 platform 做联调亦可，见下）。

本机 hosts（管理员）：

```
127.0.0.1 portal.example.com admin.example.com
```

## 前端（真 API）

```powershell
# 不要设置 VITE_AURIGA_MOCK
pnpm --filter @auriga/portal exec vite --port 5173 --host 127.0.0.1
pnpm --filter @auriga/admin exec vite --port 5174 --host 127.0.0.1
```

开发时可将 Vite proxy 指向 edge `8080`，并带正确 `Host`；或暂时把 browser 指向已配置 Host 的 edge。业务代码只依赖 `@auriga/shared` 的 API 客户端。

## 手测清单

### 应急账号 → 管理台

1. 读 `.dev/emergency-enrollment.json`（仅本机）取 `username` / `password` / `totpSecret`
2. 打开 `http://admin.example.com:8080/login`（经 edge）或等价入口
3. 选应急身份源 → 口令 → TOTP（标准 RFC 6238）→ 进入管理台
4. 确认侧栏成员 / 身份源可打开（只读或最小写）

### 团队账号：邀请 → 注册 → 登录

1. 用应急（或已有 owner）在管理台创建邀请（org 邀请 API / UI）
2. 门户打开邀请链接 → 注册（口令；若策略要求则绑 TOTP）
3. 门户口令登录（有 TOTP 则第二步）
4. 错误码与契约一致（如错误口令 `iam.invalid_credentials`）

### 管理台基本操作

- 列出身份源；可新建 OIDC（需外部 IdP 或本地 mock）
- 成员列表；角色只读或最小授权（不扩到 workspace）

### OIDC / JWKS

- OIDC 连接器已对 id_token 做 JWKS 验签（RS256/ES256）；错签密钥拒绝（见 `OidcConnectorTest`）
- 本地 HTTP Discovery 需 `auriga.iam.oidc.allow-local-http=true`（combined 已开）

### Passkey / 浏览器

- `team-account` 的 `rpId` / `origins` 必须与浏览器地址栏主机一致
- 纯 HTTP / 仅 IP 部署：`secureCookies=false`，origins 用 `http://…`
- Passkey 需 HTTPS 或 localhost；IP + HTTP 环境可能无法注册 WebAuthn

## 已知限制

| 项 | 状态 |
|---|---|
| edge ↔ iam gRPC Introspect | 未接线；依赖 NATS KV 命中或公开登录路径 |
| 会话吊销关长连接 | NATS store + `identity.session_revoked` 已接；memory 经 `OnRevoke` 已接 |
| outbox 转发 / 跨服务事件 | combined 写 outbox；需 NATS 与后续 forwarder 装配才投递 |
| ctl 不拉起 platform/edge | 仍只管 PG/NATS；用本文命令分别启动 |
| RFC1918 | 源码与文档示例禁止真实内网地址 |
