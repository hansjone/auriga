# Auriga 云端管理台设计

2026-10-23 设计提案。以 dsh-team-hub 的实际业务和 Auriga 架构、契约为依据重新组织界面，不照搬旧 Hub 的导航。此处是独立设计参考，不修改现有 `web/admin` 产品实现，也不表示各项后端能力已经交付。

## 四种界面的职责

1. **登录页**：用户已确认沿用 dsh-team 的视觉及交互，替换 Auriga 品牌并适配新的身份步骤协议。复用界面不意味着复用旧认证实现。
2. **DSH 资源页**：Auriga 插件在主界面只占一个卡槽，内部为资源市场、我的资源两个页签。
3. **DSH 设置页**：同一插件注册到宿主统一设置弹窗，Auriga 是左侧的一项；右侧处理账号、连接与插件配置。
4. **云端管理台**：独立于 DSH 的管理网站，负责平台治理。管理源与业务源、管理会话与用户会话隔离；插件接入 Key 不代替管理员身份或管理权限。

相关插件及登录设计见 [Auriga 插件设计](../auriga-plugin/README.md)。

## 重新组织后的信息架构

### 概览

首页回答“有什么要处理”和“当前是否正常”。顶部保留“总部 Agent · 系统 DSH”快捷入口；四项计数进入对应列表，主体是节点/模型异常、审核待办、最新提交、运行状态与最近操作。不使用无来源的大屏数字，不堆叠装饰性图表。示例首页标出数据为快照；正式页面应展示更新时间，无法获取的状态显示未知。

### 资源治理

集中处理 Skills、插件和工具，内部是审核队列、已发布资源、分发策略。面向管理者采用列表和详情抽屉；面向成员的插件资源页面仍使用卡片，两者目标不同。

- 审核列表展示资源、版本、类型、作者、可见范围、状态、提交时间，支持搜索和状态筛选。
- 详情优先展示版本变更、内容/文件清单、权限声明、审核记录与审核意见。审核界面不执行提交的插件或工具代码。
- 审核与发布分开：`待审核 → 审核通过/待发布 → 已上架`；驳回必须填写原因，作者不能审核或发布自己的共享版本。
- 正式审核须绑定不可变版本、内容摘要和修订号；内容变化后旧审核失效。原型只模拟状态，不伪称执行了实际扫描或签名。
- 普通下架阻止新下载、安装，不表示删除已经安装的内容。恶意版本走独立的紧急撤销与实例处置流程，离线终端不承诺即时清除。
- 等级、可见范围、版本和分发状态分别呈现。L0 随部署固定；L1 统一维护；L2 默认安装、成员可关闭；L3 成员可选；L4 本人私有、仍标未审核。正式等级变更遵守显式权限及近期身份验证。
- 分发区分已登记、已下发、应用中、已生效、失败；只有节点实际回报满足契约时才显示生效。旧版本回退也不能跳过固定版本和授权检查。

**现有契约边界**：当前 `contracts/resource/README.md` 的首批安装规格只覆盖插件，Skills 和工具在原型标为“提案”，不能冒充已有插件安装能力。用户希望公开市场面向所有 Auriga 用户；当前契约按租户及可见范围授权，不支持匿名或跨租户公开发行。界面不强调团队切换，但未来跨租户市场仍需单独补契约，不能借“公开”绕过现有授权。

### 成员与权限

成员、邀请、分组、角色放在一个入口。成员详情关联云端实例和现场终端，不展示个人会话、文件、记忆或私有模型密钥。邀请默认成员角色；提升管理权限应是独立授权操作，避免在普通邀请中随手授权超管。

角色以权限集合实现。超级管理员负责平台配置；管理员负责获授权的日常管理；资源审核员是本次建议的最小业务角色。现有身份和角色契约是实现依据，界面的角色中文名不等于已经定义的新后端权限。

### 运行环境

分为成员云端实例、现场终端、运行节点，以及单独的“总部 Agent”页签，避免将其混成“设备列表”。

- 云端实例：所属成员、节点、状态、配额、活动情况。启停先登记期望状态，再展示节点回报；启动成功还要等待就绪，不能把 HTTP 202 当完成。
- 现场终端：接入身份、系统、插件版本、连接和心跳。总部不把现场终端当作托管实例启停，也不默认获取其本地文件。
- 运行节点：驱动类型、容量、心跳、关联实例。离线状态不把旧指标显示为实时健康值。

闲置回收、常驻原因、默认配额、升级与排空放进对应配置/详情，不塞进成员的日常资源页。定时任务仍由独立插件处理；平台可保留运行时唤醒或备份调度能力，但不在此复刻用户任务编辑器。

#### 总部 Agent：平台系统 DSH（用户确认）

总部 Agent 运行在总部专属的 DSH 系统实例中，拥有独立的身份、工作区、配置和会话历史。它不归属某位管理员，不使用该管理员的个人 DSH、个人 Agent 或个人工作区。管理员是访问者和操作者；切换管理员不会切换总部实例，也不会把总部会话转移到个人空间。

界面分工如下：

- **管理台首页**：提供“总部 Agent · 系统 DSH”快捷区，主操作为“进入总部 DSH”，次操作为运行详情，不展示聊天内容或任务列表。
- **运行环境 → 总部 Agent**：展示系统实例状态、归属、运行策略、访问授权与入口；实例启停、配额、升级等属于运行管理。成员云端实例列表及其计数与总部系统实例分开，不能把总部混成管理员自己的实例。
- **总部 DSH**：使用 DSH 本身的会话界面。管理员进入后主动发起聊天、布置任务、跟进执行并查看结果；保留总部预设和获授权的工具。聊天记录、任务进展、报告与历史均由 DSH 会话和相关插件呈现。
- **取消旧管理台业务界面**：不再建设任务创建表单、任务聊天室、成员分会话正文、Agent 对话列表、报告阅读器等第二套交互界面。取消的是管理台承载位置，不意味着移除总部 Agent 能力或删除既有数据。原有通讯、任务执行与历史迁移应单独评估。

进入流程：管理员点击入口 → 服务端验证本人及总部实例访问权限 → 确定固定的总部系统实例并检查就绪 → 在新标签页打开总部 DSH → 管理员主动发送第一条消息。打开入口、加载首页、启动实例都不自动创建任务或发送提示词。若实例未启动，应先明确显示启动动作及等待就绪；不可达或启动失败则保留错误与重试入口，不转入管理员个人 DSH。

界面需持续标识“总部 Agent / 系统工作区”，以及当前操作管理员，避免多人共用系统身份时失去责任追踪。访问、启动和关键操作记录实际管理员身份；总部 Agent 执行身份单独记录，不把管理员权限无条件继承给 Agent。不同管理员可以访问同一个总部工作区，但各自登录身份、权限和审计应可区分；会话是否共享可见、并发控制与细粒度授权需在实现前落到契约。

管理台与 DSH 保持各自会话边界，通过正式授权的进入机制交接，不直接暴露系统长期凭据或复用管理 Cookie。当前原型仅展示入口和目标说明，未连接真实总部 DSH。旧 Hub `team-agents-design.zh.md` 第 6 节提供“系统实例承载总部 Agent”的依据；其中管理台发起任务、查看任务/会话的旧流程由本次用户决定替换。旧系统身份直接调用模型的能力，也不能直接绕过 Auriga G1 的身份限制，需要独立补齐总部调用授权。

总部默认模型可配置为 Auto 或获授权的明确模型；这不恢复公共知识页面或用户定时任务编辑器，也不要求在 Auriga 资源插件里新建聊天界面。

### 模型与用量

保留完整的模型中转站能力，不能缩减成模型列表。模块分成五个页签，默认进入中转站：

- **中转站**：调用入口、请求数、成功率、可用模型、Token 用量、Auto 池状态和近期调用。调用记录区分请求模型与实际服务模型，标注切换，不展示对话正文。入口示例使用保留域名；协议路径以正式契约为准。
- **提供商与模型**：按提供商分组。地址、Key 只配置一次；获取上游模型后勾选导入；模型展示对外 ID、上游模型、上下文、最大输出、输入能力与健康。模型支持独立测试；删除提供商前列出关联模型与 Auto 池的影响，避免隐性级联删除。
- **Auto 选模**：保留 `auto` 模型别名。手动优先按池顺序选择首个可用模型；自动模式在满足要求的模型间轮询，不暗示按任务语义智能选模。池支持加入、移除、上移、下移，展示健康与能力。草稿保存后生效，测试明确使用已保存配置；离开页面或更新视图将舍弃未保存的原型草稿。
- **用量**：按成员、API Key、提供商、实际模型查看；Auto 请求归入实际服务模型，同时保留 Auto 来源。计量仅涵盖网关流量，不将用户自配的个人模型调用计入。
- **API Key**：管理面向调用方签发的模型凭据，与提供商上游 Key 分开。展示归属、前缀、今日用量/上限、到期时间、最近调用与状态；签发和吊销需再次验证；完整值仅创建时展示一次。模型 Key 不用于插件接入、用户登录或管理台登录。

Auto 选模采用旧 Hub 已实现的业务逻辑作为迁移设计依据：按能力、上下文、健康与预算筛选；输出前故障最多尝试三个模型；输出开始后不切换；直接指定模型不切换。熔断由请求或管理员测试触发试探，不新增后台探测任务。原型可模拟普通文本、图片、长上下文、首选模型失败四种场景，展示筛选原因和命中模型，不伪造真实回复、耗时或 Token 统计。模拟器仅演示能力/健康筛选与顺序/轮询，不实现真实预算扣减、熔断计时或网络重试。

**必须单独处理的迁移差异**：旧 Hub 的 Auto、图片输入、外部模型 API Key 不能直接等同于 Auriga 首批已具备的能力。`contracts/ai/README.md` 的 G1 仅接受规定的实例/设备身份，只支持文本与工具消息，且明确不自动重试或故障切换。因此 Auto 和 API Key 页标注“能力规划”，迁移需补充审查后的正式契约。旧 Hub 的每日上限 `0` 表示不限，而 Auriga G1 的 `0` 配额表示禁止，不能直接复用数值语义；正式 UI 应提供明确的“不限/限额/禁止”状态并按契约映射。

云端 DSH、现场 DSH 使用同一插件，但分别走既定实例/设备认证；外部 OpenAI 兼容客户端的 Key 接入是独立能力。中转站协议兼容不代表三者认证方式完全相同。Auto 在云端管理，不放入插件设置，也不自动加进普通成员的 DSH 对话模型列表。总部 Agent 已明确由独立系统 DSH 承载，按上述流程进入；保留 Auto 不恢复公共知识管理。

### 安全与接入

身份源、访问入口、出网策略放在同一组，但各自独立授权。身份源依照 Auriga 身份步骤协议；应急账号保留恢复语义。访问入口由部署管理，界面只读显示业务源和管理源。机密字段仅显示已配置，不能回显。具体身份源配置可基于连接器描述生成表单。

### 平台运维

按处理流程聚合告警异常、备份恢复、成员离职、系统设置，取代独立的“客户端错误”“待清理”等零散入口。备份结果与恢复验证分开记录。离职分成账号停用、实例停止、资源交接、数据保留/授权处置；不做一个按钮直接删除全部数据。

### 审计日志

独立可检索入口，业务详情关联相关操作记录。记录谁在何时对哪个固定对象做了什么、结果如何、失败原因与请求关联标识；角色和授权决定可见范围。不得把凭据、个人会话内容或任意下载授权链接写入审计。

## 与旧 Hub 相比的调整

- 将旧版二十多个平铺菜单收拢成八个业务入口，相关功能使用同页子分类和详情抽屉。
- 资源审核、资源目录和插件等级归入资源治理，不再让管理员在多个顶级菜单间切换。
- 将云端实例与现场终端明确区分，并补入 Auriga 的节点视角。
- 身份源、入口、出网策略独立归于安全配置；模型服务、用量与凭据放在模型模块。
- 将审核通过、发布成功、分发登记、实际应用区分开，采用 Auriga 当前契约而不是旧 Hub 的简化状态。
- 按本轮确认范围不引入公共知识管理、个人记忆浏览或定时任务编辑。保留总部 Agent 的系统 DSH 和管理台访问入口；原管理台对话、任务、报告交互移到 DSH，由管理员主动触发，不复制第二套业务界面。
- 视觉采用简洁的浅色管理界面、细边框、克制的状态色，提供深色预览。旧文档的黑蓝玻璃风格不作为本次管理台硬约束；登录页仍沿用已确认设计。

## 可交互范围与后续实现

原型已覆盖导航、子页、搜索筛选、资源详情、必填驳回意见、禁止自审、审核/发布两阶段、普通下架、实例期望与观察状态、示例邀请、审计联动、主题和角色预览、刷新持久化。角色预览不授予真实权限。

Auto 策略、模型池与示例限额可在浏览器内保存并生成演示审计；支持选模模拟、用量维度切换。模型提供商设置、获取模型、API Key 签发流程只展示设计说明，不导入真实模型、不签发凭据。其他配置策略、模型详情、备份恢复和离职展示为只读设计示例；目前没有新增真实配置、恢复、清理、密钥管理或文件上传操作。正式产品必须实现服务端对象权限、管理员独立会话、必要的再次验证、冲突检查、失败/重试和审计；不能将前端隐藏菜单视作安全控制。

模型页面源码位于 `models.js`，由 `build.cjs` 与 `prototype.js`、`prototype.css` 一起打包为独立 `index.html`。中转站截图为 `models-preview.png`，Auto 截图为 `auto-preview.png`。

后续优先实现资源治理闭环、成员/实例基本运维和审计，再接入全局配置。变更具体角色权限、跨租户市场、工具托管或登录契约时应同步设计及契约，不直接从示例 UI 推断接口已存在。
