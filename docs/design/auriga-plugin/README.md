# Auriga 插件界面设计参考

本目录保留 2026-10-23 的交互原型，供后续插件实现和评审参考。打开 HTML 即可查看，CSS、JavaScript 和示例资源均内嵌，无需构建或联网。

## 文件与入口

- [完整交互原型](index.html)：资源市场、我的资源、工具子页及插件设置。直接打开文件后使用左侧入口切换。
- [已确认的资源页面快照](resources-2026-10-23.html)：新增设置页之前的版本，保留作者、版本、更新状态及双页签布局。
- [设置页面截图](settings-preview.png)：用于快速查看布局；交互以 HTML 为准。

完整原型支持 `#/market`、`#/mine`。`#/settings` 是直接打开设置弹窗的演示快捷入口，并不是插件主内容区的第三个页面；日常打开设置不改变资源路由，关闭弹窗保留原资源页签、筛选和滚动状态。工具使用 `#/cloud-tools/<id>` 或 `#/local-tools/<id>` 子页。

## 已确认的界面边界

- 云端 DSH 和现场 DSH 使用同一个 Auriga 插件，通过总部 URL＋Key 连接。
- 左侧属于 DSH 宿主；Auriga 只占一个业务卡槽。右侧只有“资源市场”“我的资源”两个水平页签。
- 分类、搜索后直接展示资源卡片，不重复显示页签标题及解释性文案。
- 市场与私有资源都采用卡片式布局，显示作者、版本及安装/更新状态；有新版显示可更新版本与“更新”按钮。
- Skills、插件使用“安装”；工具使用“打开”，进入独立子页面。工具支持云端或当前 DSH 本地部署。
- 总部不可达时市场直接显示不可达，本地资源仍可查看和使用；不提供离线市场缓存。
- 管理审核等在总部独立管理后台处理。当前插件不加入记忆、公共知识和定时任务。

## 登录页面（用户已确认）

登录页沿用现有 dsh-team 的视觉设计和交互，适配 Auriga 品牌及新认证接口，不另起一套视觉方案。具体以 `oclaw/dsh-team/lib/web/gate/`、Hub 现有登录界面以及 `docs/design/login-prototype.html` 为参考。

复用的是界面和交互，不是照搬旧会话实现：Auriga 登录依照 `docs/architecture/identity.zh.md` 的身份源与步骤协议承接扫码、表单、Passkey、跳转和设备确认。插件 URL＋Key 用于连接总部，用户登录用于确认身份，两者不能混为一谈；也不要求用户每次打开插件都重复登录。

云端管理台沿用同一视觉语言，但保持独立管理源、独立管理会话和权限校验，不能复用 DSH 业务会话取得管理权限。登录页、资源页面、设置页面、云端管理台分别承担认证、资源使用、插件配置、平台治理职责。

## 插件设置页设计提案

本项目是在改造现有 **dsh-team 插件**。资源页面与设置页面是两个独立界面，职责和宿主承载位置不同。设置必须在 **DSH 统一设置弹窗** 内：Auriga 直接作为弹窗左侧列表中的一项，选中后在右侧展示插件设置；不另加“插件”中间层，不把设置变成资源区整页或第三个资源页签。弹窗标题、左侧列表、关闭按钮和打开配置文件按钮属于宿主，插件只提供右侧内容。原型中的其他设置项和“打开配置文件”仅用于示意宿主布局，不实现其功能。

已核对 `oclaw/dsh-team/lib/client.js` 现有实现：

- `TeamMainPage` 通过 `main`（key 为 `dsh-team`）与 `sidebar.panellist`（id 为 `dsh-team`）注册到主界面；Auriga 资源页面应从这个业务入口改造。
- `AuthSettingsSection` 单独注册到 `settings.section`（id 为 `dsh-team`，order 为 22）。它在 `hub-member` 或 `linked` 模式下显示 `AccountSettings`，现有设置标题也按模式切换。
- `AccountSettings` 包含账号显示名、Hub 信息、安全入口以及协作偏好；本地认证设置还有关联总部、部署参数及应急账号相关功能。不能将这些现有功能默认为被 URL＋Key 表单全部替代。
- 延续 `.dsh-team-account-list`、`.dsh-team-setting` 的分组、设置行和折叠编辑形式。后续正式开发需单独梳理原账号/认证/安全功能与 Auriga 的衔接，当前原型只展示新资源插件配置提案，未实现或删除原认证功能。

设置页采用与资源页面一致的 `--dsw-alias-*` 主题变量、原生表单控件与细分隔线，包含：

1. **总部连接**：总部地址、API Key 的配置状态、输入显隐、测试连接。已配置 Key 留空保持，切换总部地址时须填写对应 Key。测试与保存分开，测试不隐式保存。
2. **工具**：默认部署位置为云端，可切换为本地；只影响新建工具的初始选项，不迁移已有工具，创建时仍可单独调整。
3. **关于**：分别展示插件版本、界面版本，体现同一插件及前端可独立更新的设计方向。原型中的版本号为示例。

页面底部折叠的“原型演示”可选择连接正常、Key 无效或已过期、总部不可达，再点击“测试连接”查看反馈。这是设计评审辅助控件，正式产品不包含它。测试结果不会改变全局连接状态；原型顶部连接状态按钮用于另一组全局离线演示。

## 原型与实现的区别

- 所有安装、更新、发布、部署、连接测试均为模拟，没有接入 Auriga 或 DSH API。
- 示例总部地址使用保留域名 `auriga.example.com`。请勿在原型输入真实凭据；输入的 Key 只留在当前表单，保存或离开后清空，不写入 localStorage。
- 浏览器仅保存原型资源、总部地址、Key“已配置”的模拟标志和默认部署选项。这个模拟标志不代表真实认证。浏览器禁用存储或使用 `file://` 时，持久化可能不可用。
- 正式实现需由插件服务端持有凭据并调用总部接口；前端只取得配置状态，不能读取已经保存的 Key。已有 Key 的替换可写入服务端，新总部地址不能复用旧总部的 Key。
- 保存配置不等于已连通；正式产品的连接状态和认证错误须来自真实调用。云端预置配置及现场权限控制由实际宿主契约决定。
- DSH 宿主壳为示意，实际接入须按宿主的 sidebar/main/settings 插槽实现。云端和现场共用插件，不复制成两套 UI。

## 后续维护

以本目录 `index.html` 为可独立打开的设计参考，历史快照保持不变。后续变更同时更新原型与本说明；不要把当前演示状态、示例版本或浏览器存储方式当成生产要求。
