# 管理审计接入边界

当前公开部署配置使用 combined platform，edge 将管理源的 `/api/audit/v1/` 转发到该入口。split 模式中该路由仍指向 `iamURL`，未配置独立审计服务路由，不能按此配置宣称 split 模式可用。邀请经 IAM gRPC 兑换时，审计记录的操作者是可信调用服务 `system/svc:iam`；combined 模式直接调用时可记录兑换成员。跨服务传递已验证的最终用户身份需要另行设计。

审计接口返回 401/403 时，以进程内固定一分钟窗口采样留痕：每个来源 IP 最多 5 条，每个已验证主体（含租户）最多 5 条，总共最多 100 条。仅保存已准入的计数键，窗口结束清空；多个实例分别限额。来源取可信请求上下文，无上下文时取实际对端，主体只取已验证的认证信息。采样和审计库故障均不修改原拒绝响应；失败仅输出固定告警，不记录请求体或凭据。

edge 转发前的拒绝尚未接耐久审计；这些请求不会到达上述采样过滤器。中心查询、详情、导出等成功访问继续按原事务逐条记录，不受拒绝采样影响。

NAS 的 `audit-db-prepare` 使用 PostgreSQL 镜像的 `999:999` 身份，renderer 生成同属主、0600 的 `postgres/audit.sql` 和 `audit-db.env`，后者仅供准备任务传入数据库口令，不挂载原 root 专用口令文件。重渲染并更新这两个文件后再运行准备任务。

中转服务已投递 outbox 行暂保留；中心审计保留期与发送队列清理策略尚未统一，未加入自动删除任务。未投递的记录始终保留用于重试。
