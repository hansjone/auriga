# IAM / gateway subject vectors

`client-subjects.json` was generated by executing the actual Go gateway
`UpSubject`, `DownSubject`, `ReplyPrefix`, and `IngressFromUp` functions from
commit `b3a374f` (`agent/codex/auriga-NETN1-GWFETCH`), not the Java implementation.
The Java `NetworkClientSubjectsTest` checks the HTTP ticket response against every
vector, including all 32 shard characters.

To reproduce the inputs, enumerate integers `n` from zero. The ticket is
unpadded base64url of `SHA256(ASCII("iam-client-vector-" + n))`. Its ingress is
lowercase unpadded RFC4648 base32 of the first 16 bytes of `SHA256(ASCII(ticket))`.
Keep the last vector seen for each shard until all 32 shards are present, then
sort by shard in ASCII order.

The gateway shard is `abcdefghijklmnopqrstuvwxyz234567[SHA256(ASCII(ingress))[0] & 31]`.
The exact subjects are:

- up: `auriga.net.up.<shard>.<ingress>`
- down: `auriga.net.down.<ingress>`
- private reply prefix: `auriga.net.reply.<ingress>` (no trailing dot or wildcard)

The shard is only a routing hint. It does not convey authorization. A legacy
unsharded up subject is rejected by the gateway.
