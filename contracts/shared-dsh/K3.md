## 2. W 正常入口探测：内部候选授权，不签公开票据

持久操作先围栏旧绑定、撤销、完成合作取消或必要停池、丢弃会话、封存/空目录及资源准备；候选绑定和 operationId 持久化，操作进入 committing，placement 仍 pending/switching。W 发起受信内部探测：身份为 W 服务主体及该操作的候选完整 Binding，另核目标成员与平台会话有效；绝不能用 owner 身份。候选身份仅允许该 operationId 的 GET 正常根页面（domain `/`、IP `/i/<physicalInstanceId>/`），去前缀后为 `/`。以新挑战响应证明请求经 E→ingress→P 正常页面处理链，不能用 health、内部 API、旧页面缓存或302跳登录冒充成功。

跨线载体、逐跳认证、头名、独立签名用途与回执详见 [PROBE.md](PROBE.md)，严格机器定义为 `probe.schema.json`。W 经内部 mTLS 端点调度，W 签名请求通过单值 `Auriga-Placement-Probe` 沿 E→ingress→P 转发，P 在正常页面完成后以独立用途密钥签回执，W 核挑战、摘要及当前尝试后提交。当前操作的探测权限限定只读页面。普通入口的 ready 检查继续适用，未实现探测接缝时保持 blocked。

探测完成须在60秒内再次锁定成员及操作，重核候选完整绑定、成员/会话、资源租约、全部必要收据和无新撤销，然后 CAS 唯一 ready 绑定并记录 succeeded、事务 outbox；失败或迟到响应不提交。外部签票/Resolve/Register/能力准入仍只允许已提交 ready。崩溃重启重新核对并探测，不能重用上次挑战。`checkSwitchProbe` 为此时序的测试 oracle，不提供生产身份签发。

## 3. W 事件：复用 CloudEvents，新增跨文件桥接

`events.schema.json` 将既有 envelope 与五种 placement data 定义按 type 关联；不复制/改变冻结 data。specversion=1.0、dataversion=1、datacontenttype=application/json、source=auriga/workspace；tenantid 来自事务可信租户，subject 按目录取 placementId、binding.placementId 或 guardian physicalInstanceId。tenantid 与 data 中全部租户、guardian 池必须一致（跨字段相等由适配器检查）。时间为业务发生时间，事件 id 为 outbox UUIDv7；Nats-Msg-Id=id，消费端按 id 持久去重。

仅 workspace 发布 `auriga.evt.placement.{switched,switch_failed,revoked,resource_reported,guardian_impact}`，ACL 沿现有 workspace 服务身份及 m3 目录生成；节点和 P 无事件发布权限。节点通过受信 NodeControl 报告，W 核所属节点/租户/当前绑定后事务写 outbox。消费者仅为目录现有列表；节点撤销仍经 NodeControl，不增加 NATS 订阅，不以事件缓存替代实时权威。协议映射必须显式输出 JSON 安全整数/必填字段，禁止直接 protojson。`checkEvent` 同时验证信封、type/data 桥接和绑定；部署发布 ACL 仍由主控接线验证。

## 4. R 成员集合：沿用撤销释放，不新增全量快照

现有 `SharedPools.RevokeMember` 及 `shared_pool_revision_test.go` 已支持成员单独释放和持久撤销围栏。成员经 prepare-empty/资源视图登记，W 为所有离池路径持久发送现有 Revocation（切换 reason=switch，禁用 reason=member-disabled）；按原节点/池路由，校验 tenant/member/placement 及严格更高 epoch/revision，重复消息幂等，旧消息不得释放新绑定。普通 logout/credential-invalid 只撤销会话/能力，不可误判成员离池。

释放前必须已完成本人取消/丢会话及必要封存的确认；未确认不释放、不清 guardian 影响。原槽位 tombstone 保留以拒绝晚 intent，不能因资源回报或一条撤销就认定全池已停。W outbox 重发到节点持久处理，重连按持久分配与未确认撤销对账；节点本地清单不是权威全量。如果无法证明撤销已处理，拒绝重启/新准入并保留旧成员用于资源授权交集核查。该方案复用现有成员串行边界与持久围栏，避免另加全量替换和删除竞态；交 W/R 实现完整重放链，当前本地 oracle 测试不证明该链已部署。

## 6. 节点内存遥测：新增精确字节消息

现有 NodeUsage/InstanceUsage 只有 MB，且无实际池硬限额，不能可靠判断整数80%边界。新增严格 `PoolMemorySample`，build-contract 生成 `SharedDshPoolMemorySample`，由 SessionRequest 新字段12承载；原9/10/11不变。这是本批唯一必要的 NodeControl 源文件增补，Go/Java/TS 按原生成链更新。

节点从运行时的整个池执行树/容器实际内存计量与硬限额同时采样，单位为字节，不得拿节点总内存、W 配置预算或 MB 反算冒充。没有可证明硬限额/采样失败就不上报有效样本，W 返回503。tenantId、physicalInstanceId、observedGeneration 必须匹配 mTLS 节点当前调度；重连/重启清掉旧连接采样，旧代数及时间倒退拒绝。0 <= observedAt <= now < validUntil，validUntil-observedAt <=30秒，W 收到后最长保留30秒，样本时间来自节点且必须校时。memoryUsedBytes 可大于 limit（展示超限），limit 必须正且全部安全整数；准入采用 used*100 >= limit*80 整数比较。W 结合全部同租户池新鲜样本和自身登记/活跃/预留构建快照，任一池缺失则503；准入时再次检查。旧节点未支持字段12时不可开启依赖它的共享容量展示/准入。
